# 화면 설계 (v1)

원칙: **터미널이 주인공이다.** relay의 UI는 터미널 바깥에서 "지금 어디에 있고, 무엇을 기다리며, 무엇이 주입됐는가"를 보여 준다. 터미널 안에는 아무것도 그리지 않는다.

---

## 1. 전체 배치

```
┌────────────┬───────────────────────────────────────────────────┬──────────────────────┐
│ 사이드바     │ Work 헤더                                          │ 오른쪽 패널            │
│            │  KST 토큰 만료 버그  [● 진행 중]  intent v1  bugfix·M  │ [검토][컨텍스트][기록]   │
│ ▾ my-api   │  ┌ 스텝퍼 ─────────────────────────────────────────┐ │                      │
│   ● w-001  │  │ intake ✓ ─ 의도 ✓ ─ evidence ✓ ─ rca ● ─ fix ─  │ │  (탭 내용, 2절)        │
│   ! w-002  │  │ 테스트 ─ verify ─ 완료                          │ │                      │
│   ‖ w-003  │  └────────────────────────────────────────────────┘ │                      │
│   + 새 Work │  Task 탭: [01 intake 🔒][03 evidence 🔒][04 rca ●]   │                      │
│ ▸ web-app  │ ┌────────────────────────────────────────────────┐  │                      │
│            │ │                                                │  │                      │
│            │ │            터미널 (xterm.js)                    │  │                      │
│ + 프로젝트   │ │                                                │  │                      │
│            │ └────────────────────────────────────────────────┘  │                      │
│ ⚙ 설정      │ 액션 바: [Task 완료] [다음 단계 변경 ▾] [의도 수정] ⋯  │                      │
└────────────┴───────────────────────────────────────────────────┴──────────────────────┘
```

- 사이드바, 오른쪽 패널은 접을 수 있다. 창 폭이 1280px 미만이면 오른쪽 패널은 기본으로 접힌다(기본값).
- 단축키(기본값): `Ctrl+Enter` Task 완료(승인 가능할 때만), `Ctrl+Shift+R` 다음 단계 변경, `Ctrl+1..9` task 탭 이동. 터미널에 포커스가 있을 때는 터미널이 키를 먼저 받으므로 relay 단축키는 `Ctrl+Shift` 조합만 쓴다.

## 2. 영역별 설계

### 2.1 사이드바: 프로젝트 / Work 탐색

- 프로젝트 → Work 두 단계 트리. Work 줄: 상태 배지 + 제목(intent 승인 전에는 요청 첫 줄) + 오른쪽에 대기 표시.
- 정렬: `needs_attention` > 승인 대기 > 입력 대기 > 진행 중 > 일시 정지 > 완료/포기. 완료·포기 Work는 "지난 Work" 접힌 그룹.
- `archived` Work는 사이드바에 없다. [보관함]에서 산출물만 읽기 전용으로 본다.
- 백그라운드 Work(선택되지 않은 Work)에서 승인 대기, 입력 대기, 검사 실패, `needs_attention`이 생기면 배지가 깜박이고, 창이 비활성이면 OS 알림을 띄운다.

### 2.2 상태 배지

| Work 상태 | 배지 | Task/step 상태 | 탭·스텝퍼 표시 |
|---|---|---|---|
| active | 파랑 ● | running | 파랑 ● (턴 진행 중이면 회전) |
| needs_attention | 주황 ! | running + 입력 대기(Notification) | 노랑 ⌨ "입력 대기" |
| paused | 회색 ‖ | awaiting_approval | 보라 ◆ "승인 대기" (카운트다운 중이면 남은 초) |
| completed | 초록 ✓ | approved | 초록 ✓ + 🔒 |
| abandoned | 회색 ✕ | abandoned | 회색 ✕ + 🔒 |
| | | interrupted / ended_no_handoff | 주황 ⚠ |
| | | gate passed / failed / skipped | ✓ / 빨강 ✕ / 점선 테두리 |

색만으로 구분하지 않고 기호를 함께 쓴다(색각 이상 대응).

### 2.3 스텝퍼

- 파이프라인 스냅숏의 노드를 순서대로 표시. `when` 때문에 건너뛸 노드는 점선으로 흐리게("S 규모라 건너뜀" 툴팁).
- 같은 노드가 여러 번 실행되면 노드 아래에 횟수(`fix ×3`).
- 임시 노드(기타 스킬, intent-revise)는 현재 위치에서 아래로 갈라진 가지로 표시하고 복귀 지점을 화살표로 보인다.
- stale 산출물을 가진 노드에는 "의도 v2 이후 재검토 필요" 표시.
- 노드를 클릭하면 그 노드의 가장 최근 step 탭으로 이동한다.

### 2.4 Task 탭과 터미널

- 탭 하나 = step 하나. skill step은 터미널, gate step은 결과 화면(검사 표와 로그, human 게이트는 승인 화면).
- **task 경계는 숨기지 않는다.** 새 task가 열리면 새 탭이 열리고, 터미널 맨 위에 relay가 그리는 **머리 띠**(터미널 바깥, xterm 위의 HTML 요소)를 붙인다:
  `t-05 · fix · 새 세션 · 들어온 이유: 테스트 실패 (g-tests 1회차) · 주입된 컨텍스트 7.2k 토큰 [보기]`
- 들어온 이유 문구: 기본 진행 / 테스트 실패로 복귀 / 추천에 따라 이동 / 사용자가 경로 변경 / 의도 개정 후 재개 / 임시 노드.

**읽기 전용 task**
- 승인·포기된 task의 탭은 🔒 표시. 터미널은 `pty.log`를 재생한 화면이며 입력을 받지 않는다(커서 숨김, 회색 머리 띠 "읽기 전용 · 승인됨 10:42 · 자동").
- 스크롤, 선택, 복사, 검색(`Ctrl+F`)은 된다.
- [이 세션 기록 열기]: Claude Code transcript 파일을 외부 편집기로 연다.
- 앱 재시작 후에도 같은 화면을 재생한다(`pty.log`). 로그가 상한을 넘어 앞부분이 잘렸으면 머리 띠에 표시한다.

**실행 중 task의 터미널 닫기**
- 탭의 닫기 버튼은 실행 중 task에는 없다. 대신 ⋯ 메뉴의 [Task 중단]이 있고, 확인 대화상자("세션을 종료합니다. 나중에 이어서 할 수 있습니다")를 거친다 → `interrupted`.
- 사용자가 터미널 안에서 `/exit` 등으로 CLI를 끝낸 경우는 design.md 8.2의 "CLI 종료" 처리를 따른다.

### 2.5 액션 바와 승인

액션 바는 현재 step 상태에 따라 바뀐다.

| 상태 | 주 버튼 | 보조 |
|---|---|---|
| running (handoff 없음) | (비활성) Task 완료 — 툴팁 "에이전트가 handoff를 쓰면 활성화됩니다" | 다음 단계 변경, 의도 수정, [지금 검토] |
| running (handoff 있음, 턴 진행 중) | (비활성) "턴이 끝나면 검토할 수 있습니다" | 같음 |
| awaiting_approval (유효) | **Task 완료 → 다음: rca** | 다음 단계 변경, 의도 수정 |
| awaiting_approval (형식 오류) | (비활성) Task 완료 | [형식 오류 무시하고 승인…] (확인 대화상자), 오류 목록은 검토 탭 |
| awaiting_approval (blocked) | 다음 단계 선택… | 의도 수정 |
| intake awaiting_approval (다음이 g-intent) | **의도 승인** (task 승인 + 게이트 통과를 한 번에, D37) | 다음 단계 변경 |
| verify awaiting_approval (다음이 g-done) | **Work 완료** (delivery 요약: "draft PR 생성") | ▾ 승인만 하고 완료는 나중에, 다음 단계 변경 |
| human gate 단독 (합치지 않은 경우) | **의도 승인** / **Work 완료** | 다음 단계 변경 |

**비기본 다음 노드 추천**: 주 버튼이 `Task 완료 → 다음: fix (추천: "원인 확정")`처럼 추천을 반영하고, ▾로 기본 노드를 고를 수 있다.

**자동 승인 카운트다운**
```
┌ 자동 승인 ───────────────────────────────────────────────┐
│ ◆ 12초 뒤 자동으로 승인하고 g-tests로 진행합니다   [취소] [지금 승인] │
│ ✓ handoff 형식  ✓ 열린 질문 없음  ✓ 의도 이탈 없음            │
│ ✓ repro:passes  ✓ repro:intact  ✓ tests:unchanged  ✓ cmd:test  │
│ ✓ 커밋 완료  ✓ diff 84줄/3파일 (한도 300/10)   연속 자동 승인 1/3 │
└──────────────────────────────────────────────────────────┘
```
- 터미널에 키를 입력하면 "입력 중이라 멈춤"으로 바뀌고 `pause_on_input_sec` 뒤 다시 센다.
- [취소]하면 수동 승인으로 남는다(같은 task에서 다시 자동으로 시작하지 않음. 다음 Stop에서 조건이 바뀌면 재평가).
- 자동 승인이 안 될 때도 같은 목록을 ✕와 이유와 함께 보여 준다("✕ 열린 질문 1개"). 사용자는 항상 왜 수동인지 안다.

### 2.6 오른쪽 패널

**[검토] 탭 — 산출물 검토**
- 위: handoff 요약 카드 (요약, 결정 목록(사람/AI 표시, `requires_human`인데 AI가 정한 것은 강조), 열린 질문, 의도 이탈, 위험, 추천 다음 단계).
- 아래: 산출물 목록 → 클릭하면 마크다운 렌더링. 코드를 바꾼 task는 [diff] 항목: `start_head..end_head` 파일 목록과 diff(읽기 전용, 테스트 파일 변경은 강조).
- rca 승인 화면에는 **고정된 재현 테스트** 카드(파일, 실패 출력 끝부분, 고정 커밋)를 함께 보여 준다(state-machine.md 4.1).
- handoff 형식 오류: 오류 목록(필드 경로 + 한국어 설명) + [파일 열기].
- 산출물을 고치고 싶으면 터미널에서 에이전트에게 말한다. 패널은 편집기가 아니다. 예외로 [외부 편집기로 열기]는 제공한다(사람이 직접 고치면 handoff 변경으로 감지되어 재검증).

**[컨텍스트] 탭 — 주입된 컨텍스트**
```
이 세션에 주입된 것 (7,180 / 8,000 토큰)
 inline  gate-policy            120
 inline  next-options            90
 inline  intent@v1              640
 inline  gate-failure (g-tests)  880   ← 1회차 실패 로그 끝 80줄
 inline  decisions              410
 inline  rejected-log           220
 inline  prev-handoff           950
 path    handoff-chain        2,300   (강등됨: 예산 초과)
 path    rca/rca.md           1,800
 path    evidence/evidence.md ⚠stale
 path    transcript t-04
[context.md 전체 보기]  [첫 프롬프트 보기]
```
- 조각을 누르면 실제 주입된 텍스트를 보여 준다. 강등, stale, missing 표시.

**[기록] 탭** — 이 Work의 이벤트 타임라인(events.jsonl), 결정 로그(decisions.md), intent 버전 기록과 차이.

## 3. 주요 대화상자

| 대화상자 | 내용 |
|---|---|
| 프로젝트 등록 | design.md 7.1 절차의 단계 화면(폴더 선택 → 탐지 결과 확인·수정 → 테스트 명령 시험 실행(선택) → 저장) |
| 새 Work | 프로젝트, 파이프라인(v1: 버그 수정만, 선택지로 보이되 하나), 요청 입력(여러 줄, 이슈 링크나 로그 붙여넣기). [시작]하면 worktree·setup 진행 표시 후 intake 탭이 열림 |
| 다음 단계 변경 | 세 그룹(기본 / 허용된 전이 / 기타 스킬). 각 항목에 한 줄 설명, `requires` 미충족 경고. 실행 중 task가 있으면 "현재 task를 중단합니다(산출물 보존)" 문구 |
| 의도 수정 | 수정 계기 입력(선택). 실행 중 task 중단 경고. [의도 개정 task 시작] |
| Work 포기 | 사유 입력(선택). worktree는 남음, 나중에 [Work 정리] |
| Work 정리 | design.md 7.4의 확인 결과 표, 브랜치 삭제 선택(기본 유지) |
| needs_attention | 이유와 선택지 버튼(state-machine.md 3.4). 사이드바 Work를 선택하면 액션 바 위에 띠로 표시 |

## 4. 첫 실행과 빈 화면

1. 도구 점검 화면: `claude`, `git`, (선택) `gh` 탐지 결과와 버전. 없으면 설치 안내 링크. `claude`가 로그인되지 않았으면 "터미널 탭에서 `claude`를 한 번 실행해 로그인하세요" 안내와 [로그인용 터미널 열기] (relay 관리 밖의 일반 PTY).
2. 프로젝트가 없으면 가운데에 [프로젝트 등록].
3. Work가 없으면 [새 Work]와 버그 수정 파이프라인 한 줄 설명.
