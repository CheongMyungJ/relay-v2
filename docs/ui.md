# 화면 설계 (v1, 문서 v0.3)

원칙:
1. **터미널이 주인공이다.** relay의 UI는 터미널 바깥에서 "지금 어디에 있고, 무엇을 기다리며, 무엇이 주입됐는가"를 보여 준다. 터미널 안에는 아무것도 그리지 않는다.
2. **상태보다 다음 행동.** 모든 화면의 첫 줄은 "지금 누가 무엇을 해야 하는가"다. 내부 상태 이름(active, awaiting_approval)은 보조 정보로만 보인다.
3. **task 경계는 숨기지 않는다.** 새 세션은 새 탭이고, 왜 이 단계에 왔는지가 첫 줄에 보인다.

---

## 1. 전체 배치

```
┌────────────┬──────────────────────────────────────────────────────┬──────────────────────┐
│ 내 조치 필요 2 │ KST 토큰 만료 버그 · bugfix·M · 의도 v1                    │ 오른쪽 패널            │
│  ◆ w-001 승인 │ ▶ 내 승인 필요: 원인 분석 결과를 검토해 주세요              │ [검토][컨텍스트][기록]   │
│  ⌨ w-004 입력 │ ┌ 단계 ───────────────────────────────────────────┐  │                      │
│────────────│ │ 의도 ✓ ─ 증거 ✓(A) ─ 원인 ◆ ─ 수정 ─ 검증 ─ 완료      │  │  (탭 내용, 2.6절)      │
│ ▾ my-api   │ └──────────────────────────────────────────────────┘  │                      │
│   ◆ w-001  │ 탭: [01 의도 🔒][03 증거 🔒][04 원인 ◆]  ▸ 이전 시도 2      │                      │
│   ● w-002  │ ┌ 04 원인 분석 · 새 세션 · 이유: 기본 진행 ──────────────┐ │                      │
│   ‖ w-003  │ │                                                  │ │                      │
│   + 새 Work │ │            터미널 (xterm.js)                      │ │                      │
│ ▸ web-app  │ │                                                  │ │                      │
│ + 프로젝트   │ └──────────────────────────────────────────────────┘ │                      │
│ ⚙ 설정      │ [승인하고 수정 단계로 ▾]  다음 단계 변경  의도 수정  ⋯        │                      │
└────────────┴──────────────────────────────────────────────────────┴──────────────────────┘
```

- **Work 헤더 둘째 줄 = 주 상태 문장.** 예: "에이전트 작업 중", "입력 대기: 권한 확인이 필요합니다", "내 승인 필요: 원인 분석 결과", "검사 실행 중 (프로젝트 대기열 2번째)", "세션 대기: 동시 세션 3/3 사용 중 — w-002, w-003", "자동 승인 12초 전".
- 사이드바 맨 위 **"내 조치 필요" 고정 목록**: 승인 필요, 입력 필요, needs_attention인 Work를 발생 시각 순으로. 아래 프로젝트 트리는 정렬이 바뀌지 않아 선택한 줄이 움직이지 않는다.
- 사이드바와 오른쪽 패널은 접을 수 있다. 창이 좁아 오른쪽 패널이 접혀 있어도 **승인이 필요하면 액션 바 위에 검토 요약 띠**(2.5)가 자동으로 나온다.
- 단축키(기본값): `Ctrl+Shift+Enter` 승인(버튼이 활성일 때만), `Ctrl+Shift+R` 다음 단계 변경, `Ctrl+Shift+1..9` 탭 이동. 터미널이 일반 키를 먼저 받기 때문에 `Ctrl+Shift` 조합만 쓴다.

## 2. 영역별 설계

### 2.1 사이드바

- 프로젝트 → Work 두 단계 트리. Work 줄: 행동 배지 + 제목(intent 승인 전에는 요청 첫 줄).
- 완료·포기 Work는 "지난 Work" 접힌 그룹. `archived`는 [보관함]에서만 보인다.
- 백그라운드 Work에 조치가 필요해지면 "내 조치 필요" 목록에 추가되고, 창이 비활성이면 OS 알림을 띄운다.

### 2.2 상태 표시 체계

두 체계를 섞지 않는다.

**(1) 행동 배지** — 사이드바, 헤더, 알림에 쓰는 사용자 기준 상태. Work마다 하나.

| 배지 | 뜻 | 파생 조건 |
|---|---|---|
| ◆ 승인 필요 | 사람이 승인 버튼을 눌러야 진행 | 현재 step에 유효 후보가 있고 수동 승인 대상 / human 게이트 대기 |
| ⌨ 입력 필요 | 에이전트가 사람을 기다림 | Notification `permission_prompt`, blocked handoff(세션 살아 있음) |
| ! 선택 필요 | 앱이 다음을 정할 수 없음 | `needs_attention` |
| ⏱ 자동 진행 중 | 카운트다운 | 자동 승인 카운트다운 |
| ● 작업 중 | 에이전트나 검사가 일하는 중 | 턴 진행 중, 검사 실행 중 |
| ○ 대기 | 세션은 있고 에이전트는 응답을 마침 | 턴 종료 후 handoff 없음(대화 중). `idle_prompt` 알림이 오면 "응답 후 입력 없음"으로 보조 표시 |
| ‖ 멈춤 | 일시 정지, 세션 상한 대기 | `paused` |
| ✓ / ✕ | 완료 / 포기 | |

Notification은 유형별로 다르게 다룬다: `permission_prompt`만 "입력 필요"로 올리고, `idle_prompt`(응답 후 약 60초)는 보조 표시, 그 밖의 알림은 기록만 한다.

**(2) 단계 표시** — 스텝퍼와 탭에만 쓰는 이력 상태: ✓ 승인(사람) / ✓(A) 자동 승인 / ◆ 현재 / ⚠ 중단됨 / ✕ 포기 / 점선 = 건너뜀. 색만으로 구분하지 않고 기호를 함께 쓴다.

### 2.3 스텝퍼

- **논리 단계 요약만** 담당한다. 노드를 순서대로, 건너뛸 노드는 점선("S 규모라 건너뜀"). 경로 승격(D41) 후에는 점선이 실선으로 바뀌고 "S 경로를 벗어나 전체 경로로 진행 중" 표시.
- 반복 실행은 노드 아래 `×3`. 클릭하면 **시도 목록**(각 시도의 이유, 결과, 탭 열기)을 펼친다.
- 임시 노드(기타 스킬, 의도 개정)는 현재 위치에서 갈라진 가지로, 복귀 지점을 화살표로 보인다.
- 재검토가 필요한 입력(stale `review`)을 쓰는 노드에 "의도 v2 이후 재검토" 표시.

### 2.4 Task 탭과 터미널

- 탭 하나 = step 하나. 기본으로 **현재 task와 직전 두 개**만 보이고, 나머지는 "▸ 이전 시도 N"으로 접힌다.
- 새 task의 **머리 띠**(터미널 위 HTML 요소) 첫 줄은 이유다:
  `04 원인 분석 · 새 세션 · 이유: 수정 단계에서 "증상과 코드가 맞지 않음"으로 돌아옴`
  이유 문구: 기본 진행 / 사용자가 검사 실패 후 보냄 / 추천에 따라 이동 / 사용자가 경로 변경 / 의도 개정 후 재개 / 임시 노드 / 다시 시작.
  둘째 줄(접힘): 세션 id, 주입 컨텍스트 7.2k 토큰 [보기], 재개 횟수.

**읽기 전용 task** (승인·포기됨)
- 🔒 표시, `pty.log` 재생 화면, 입력 불가. 스크롤·선택·복사·검색(`Ctrl+F`)은 된다.
- 머리 띠: "읽기 전용 · 승인됨 10:42 · 자동 · 후보 abc123".
- [이 세션 기록 열기]: transcript를 외부 편집기로.

**실행 중 task 닫기**: 탭 닫기 버튼 없음. ⋯의 [Task 중단](확인 → `interrupted`).

### 2.5 액션 바와 승인

**승인 요약 띠** — 승인이 필요하면 액션 바 바로 위에 항상 나온다(오른쪽 패널이 접혀 있어도).

```
┌ 수정 결과 승인 — 다음: 최종 검증 ───────────────────────── 후보 abc123 · 의도 v1 ┐
│ 사람이 확인할 것  ⚠ 기존 테스트 1개 변경됨 → [변경 보기]                              │
│ 앱이 확인한 사실  ✓ 전체 테스트  ✓ 재현 테스트 통과  ✕ 재현 테스트 파일 변경됨            │
│ 에이전트 보고     수정 요약 · 남은 위험 1 · 의도 이탈 없음            [전체 검토 열기]     │
└──────────────────────────────────────────────────────────────────────────┘
 [승인하고 최종 검증으로 ▾]   [재고정…] [고정 해제…]   다음 단계 변경   ⋯
```

순서는 고정이다: ① 현재 판단과 다음 단계 ② 검토 대상(후보 해시, 의도 버전, 변경 규모) ③ **사람이 확인할 것**(2~3개, 해당 diff/문서로 바로 가는 링크) ④ 앱이 확인한 사실 ⑤ 에이전트의 보고(에이전트가 적은 결정 주체는 "에이전트 보고"로 표기) ⑥ 행동.

"사람이 확인할 것"을 만드는 규칙(기본값): 테스트·테스트 설정 파일 변경, 재현 테스트 변경, `requires_human` 결정, 열린 질문, 의도 이탈, 기본이 아닌 추천, 형식 오류.

**버튼 상태**

| 상황 | 주 버튼 | 보조 |
|---|---|---|
| 에이전트 작업 중 / handoff 없음 | (비활성) "에이전트가 결과를 쓰면 검토할 수 있습니다" | 다음 단계 변경, 의도 수정, [지금 검토] |
| 유효 후보 | **승인하고 <다음 단계>로** (▾: 다른 허용 노드) | 다음 단계 변경, 의도 수정 |
| intake 후보 | **의도 승인** (task 승인 + 게이트 통과 한 번에) | ▾ 승인만 |
| verify 후보 | **Work 완료** / **완료하고 draft PR 생성** | ▾ 승인만 하고 완료는 나중에 |
| 형식 오류 | (비활성) + 오류 목록 | [형식 오류 무시하고 승인…] |
| blocked (세션 살아 있음) | 안내: "에이전트가 정보가 필요합니다: <이유>. 터미널에 답해 주세요" | 다음 단계 선택(보조) |
| `repro:intact` 실패 | 승인 가능(수동) | [변경된 테스트로 재고정…] [고정 해제…] |
| 후보 불일치로 무효 | "검토 후 내용이 바뀌었습니다. 다시 확인해 주세요" + 새 요약 | — |

승인 클릭은 **화면에 표시된 후보 id**와 함께 전송된다. 그 사이 후보가 바뀌었으면 거절하고 새 요약을 보여 준다(C1).

**자동 승인 카운트다운**
```
⏱ 12초 뒤 자동으로 승인하고 최종 검증으로 진행합니다   [이번 결과는 직접 검토] [지금 승인]
```
- 터미널에 키를 누르면 "입력 중이라 멈춤", 프롬프트를 **제출하면 카운트다운과 후보가 사라진다**(새 턴이므로).
- [이번 결과는 직접 검토]: 이 후보만 수동으로 돌린다. 다음 후보(새 턴 이후)는 다시 평가한다.
- 자동 승인이 안 될 때는 조건을 "원인 → 할 일"로 한 줄씩: "✕ 기존 테스트 변경 → 변경 보기 후 직접 승인", "✕ 전체 테스트 실패 → 로그 보기 · 터미널에서 수정 요청".
- 검사 결과는 "실행 통과 / 적용 대상 없음(n/a)"을 다른 기호로 보인다.

### 2.6 오른쪽 패널

**[검토] 탭**
- handoff 요약 카드(요약, 결정 목록 — "에이전트 보고: 사람/AI", 열린 질문, 의도 이탈, 위험, 추천).
- 산출물 목록 → 마크다운 렌더링. [외부 편집기로 열기](사람이 고치면 변경 감지 → 후보 재생성).
- **diff 세 범위 탭**(I14): [이번 task 변경] `start_head..후보 head` / [전체 Work 변경] `base_commit..후보 head` / [테스트·검증 설정 변경]. verify와 Work 완료 화면의 기본 탭은 **전체 Work 변경**.
- rca 화면에는 **고정된 재현 테스트** 카드(파일, 실패 출력 끝부분, 고정 커밋, "올바른 이유로 실패하는지 확인하세요").

**[컨텍스트] 탭** — 이 세션에 주입된 조각 목록(inline/path, 토큰, 강등·stale·missing 표시), [context.md 전체 보기], [첫 프롬프트 보기].

**[기록] 탭**
- **Work 요약**(완료된 Work를 열면 기본): 의도 버전별 변화, 주요 결정(사람 확정), 되돌아간 지점과 이유(`task.rerouted`의 참조·메모), 최종 검사 결과, 전달 결과(PR 링크).
- 이벤트 타임라인, decisions.md, intent 버전 차이.

## 4. 첫 실행과 빈 화면

1. 도구 점검: `claude`(필수), `git`(필수 — relay의 worktree 기능), `gh`(PR 전달 시). `claude` 미로그인이면 [로그인용 터미널 열기] (relay 관리 밖의 일반 PTY).
2. 프로젝트가 없으면 가운데에 [프로젝트 등록].
3. Work가 없으면 [새 Work]와 버그 수정 파이프라인 한 줄 설명.
