# 세션이 하고 앱은 보는 자율 Work

- 상태: 구현함 (D557~D562, M50). 평가는 11절과 13절. 앱의 독립 리뷰(처음 설계의 D559)는 12절대로 없앴다
- 작성일: 2026-11-02
- 범위: 자율 유형(`auto`)만. 다른 유형은 지금 그대로 둔다.

이 문서는 자율 Work를 "앱이 단계와 전달을 쥔다"에서 "동작은 세션이, 앱은 감지하고 보여 준다"로 바꾸는 설계다. 정한 것은 [design.md](design.md) 2절의 D557~D562로 옮겼다. 앞선 자율 Work의 설계와 평가는 [autonomous-work.md](autonomous-work.md)에 있다.

## 1. 왜 바꾸나

relay는 처음부터 앱이 흐름을 쥐었다. 단계마다 handoff 형식을 검사해 되돌리고, push와 PR을 막고(D17), 전달과 PR 대응을 앱이 했다. 고정 유형에서는 이 장치가 사람의 수고를 덜었다. 자율 Work에서는 거꾸로 제약이 됐다.

- **자식 결과를 따로 PR로 낼 길이 없다.** 세션은 push와 `gh pr`이 막혀 있고, 앱이 대신 내던 `decide_child pr`은 D556에서 없앴다.
- **앱이 끼면 경합과 형식 비용이 생긴다.** 평가 43에서 `decide_child`가 자식의 턴이 끝나기 전에 불려 거절됐다. 평가 40에서는 자식 셋이 handoff 형식 오류로 다섯 번 되돌려졌고, 그때마다 부모가 깨어나 토큰을 썼다.
- **Claude Code가 이미 할 줄 안다.** 브랜치, PR, CI 실패와 리뷰 코멘트 대응, 세션 간 대화를 한다. Claude Code 데스크톱 앱과 Projects도 이렇게 둔다. 자식 세션은 PR을 직접 열고, 앱은 세션을 보여 주고 정리(보관)만 한다.

## 2. 무엇을 남기나

평가에서 relay가 맨 CLI를 이긴 것은 의도 정리에서 사람만 아는 규칙을 끌어낸 데서 크게 나왔다(08, 07). 그래서 강제는 의도 정리와 위험한 동작 막기만 남기고 나머지는 감지해서 보여 준다. (처음 설계는 독립 리뷰도 앱이 강제했으나 12절대로 없앴다.)

| 구분 | 무엇 | 방식 |
|---|---|---|
| 강제 | 의도 정리와 사람의 의도 승인 | 지금 그대로. 사람이 끼는 유일한 관문이다 |
| 강제 | 위험한 git·gh 동작만 막기 | 머지 대상·기준 브랜치와 `main`·`master`에 push, 강제 push, 원격 브랜치 지우기, `gh pr merge`를 PreToolUse 훅이 막는다. 작업 브랜치 push와 PR 열기는 허용한다 (D558) |
| 세션 | 리뷰 | 할지, 언제 어떻게 할지 세션이 정한다. 앱은 돌리지 않고 지침도 넣지 않는다 (D562) |
| 감지·표시 | 나머지 | 계획(plan.md가 있으면), 서브에이전트, 자식 세션 트리, 커밋, push한 브랜치, PR (D560) |
| 사람 | Work 끝내기 | 사람이 [Work 완료]를 누른다. 앱은 기록만 남기고 전달하지 않는다. 내보내기는 세션이 이미 했다 (D561) |

PR 머지는 사람이 GitHub에서 한다. 되돌리기 어려운 마지막 단계는 앱이 쥐지 않아도 사람 손에 남는다.

## 3. 걷어내는 것 (자율 유형에서만)

| 걷어내는 것 | 대신 |
|---|---|
| 자율 진행의 마무리 단계(판정표, `verification.md`, `pr.md`, 지식 남기기, Work 완료 화면의 전달 선택) | 사람의 [Work 완료]. 판정표가 필요하면 세션이 PR 본문에 쓴다 |
| plan.md 관문(방식 이름, 시험 먼저 커밋 차례, `(테스트 못 더함)` 줄)과 형식 되돌림 | 없음. plan.md는 있으면 보여 준다 |
| handoff 요구 | 없음. 세션은 턴을 끝내면 쉰다(자식과 같음, D555) |
| push·`gh pr` 막기(D17) | 위험한 동작만 막는 훅(D558) |
| 앱의 전달(push, PR 만들기)과 PR 진행 상태 | 세션이 push하고 PR을 연다. 앱은 PR을 찾아 보여 준다 |

의도 정리(intake)는 그대로다. 의도 정리의 산출물, 형식 검사, 사람 승인도 지금과 같다.

## 4. 세션이 받는 것

자율 진행의 시스템 프롬프트(`skills/types/auto/orchestrate.md`)는 사실만 담는다.

- 목표: 승인된 의도(context.md의 경로).
- 하는 방법은 세션이 정한다: 전략, 나누기, 서브에이전트, 자식 세션, 시험, 커밋, push, PR.
- 앱이 하는 일: 위험한 git·gh 동작을 막는다(무엇을 막는지). 사람이 [Work 완료]를 누르면 Work가 끝난다.
- 자식 세션 도구와 말하는 법(D556 그대로).
- 사람이 진행을 보는 곳: `plan.md`(있으면 계획 칸에 보인다).

이번 범위에서 "언제 사람에게 묻는가"는 한 줄만 남긴다: 사람만 아는 사실이 필요하거나 범위를 넓힐 때. 의도 정리가 대부분을 먼저 묻는다.

## 5. 앱이 감지하는 것

| 무엇 | 어디서 | 언제 |
|---|---|---|
| 세션이 일하는지, 쉬는지 | 훅(UserPromptSubmit, Stop) | 지금 그대로 |
| 도구와 서브에이전트 | 훅(PreToolUse, PostToolUse) | 지금 그대로 (D216, D542) |
| 계획 | task 디렉터리의 plan.md | 파일이 바뀔 때 (D542) |
| 커밋 | Work worktree의 git | 턴이 끝날 때 |
| push한 브랜치 | 원격 추적 참조(`refs/remotes/origin/*`) 가운데 이 Work의 기준 커밋 뒤에 커밋이 있고 다른 Work의 브랜치가 아닌 것. push는 원격 추적 참조를 고친다 | 턴이 끝날 때, push 명령 뒤 |
| PR | 브랜치마다 `gh pr list --head` | push한 브랜치가 바뀔 때. gh가 없거나 실패하면 비워 둔다 |
| 자식 세션 | 자식 Work의 상태, 합쳐졌는지(D556) | 지금 그대로 |

## 6. 독립 리뷰 (처음 설계, D562로 없앰)

- **언제:** Work 브랜치의 push를 감지했을 때(PostToolUse의 Bash가 `git push`이고, 원격 추적 참조의 Work 브랜치 끝이 리뷰한 커밋과 다를 때). Work당 자동 두 번까지. 사람은 [독립 리뷰]로 언제든 돌린다.
- **무엇을:** 지금 마무리 단계의 독립 리뷰(D495)와 같은 찾기·확인을 기준 커밋부터 HEAD까지에 돌린다. 결과 글은 task 디렉터리의 `independent-review.md`에 쓴다.
- **결과:** 세션에 한 줄 안내와 결과 글 경로를 보낸다. 반영할지는 세션이 정한다. 화면은 지적 수와 등급별 개수, 리뷰한 커밋을 보인다. 막지 않는다.
- **자식:** 자식의 push는 자동 리뷰하지 않는다. 부모 브랜치에 합쳐지면 부모의 리뷰가 본다. 따로 나가는 자식 PR의 리뷰는 부모가 지시로 정한다.

자동을 두 번으로 막는 까닭: 세션이 리뷰를 반영해 다시 push하면 또 리뷰가 돈다. 이 순환이 끝없이 이어지지 않게 한다.

## 7. Work 끝내기

- 사람이 [Work 완료]를 누르면 앱이 자율 진행 task에 기록용 handoff를 쓰고 승인한다. Work는 전달 없이 완료되고(`delivery: none`) 세션은 끝난다. 자식 Work를 닫는 길(D556)과 같다.
- 세션이 일하는 중이면 누를 수 없다. 끝나지 않은 자식이 있으면 확인을 한 번 묻는다.
- PR이 머지되면 Work를 저절로 끝내는 것은 이번에 넣지 않는다(11절의 남은 것).

## 10. 들이지 않은 대안

| 대안 | 들이지 않은 까닭 |
|---|---|
| 모든 유형을 한 번에 바꿈 | 전달, PR 대응, 정리, 지식 관리처럼 앱이 쥔 것이 많아 위험이 크다. 자율에서 평가로 확인한 뒤 옮긴다 |
| 앱이 독립 리뷰를 돌림(처음 설계) | 12절. 평가에서 값을 하지 못했고, 사람이 처음 바란 것은 세션이 정하는 것이었다 |
| 독립 리뷰를 프롬프트 지침으로 | 모델이 좋아질수록 효과가 희미해진다. 세션은 서브에이전트나 리뷰 기능으로 스스로 할 수 있다(사람과 정함) |
| 독립 리뷰가 막는 관문 | 형식 되돌림과 같은 비용과 경합이 다시 생긴다. 결과를 보여 주고 세션과 사람이 정한다 |
| 턴이 끝날 때마다 리뷰 | 부모는 자식을 기다리거나 사람에게 물을 때도 턴을 끝낸다. 덜 된 것을 리뷰하게 된다 |
| push를 모두 허용 | 머지 대상에 바로 push하거나 강제 push하면 되돌리기 어렵다. 이 몇 가지만 막는다 |
| 앱이 리뷰 결과를 PR 코멘트로 게시 | 바깥에 쓰는 일이다. 세션이 PR 본문에 옮길지 정한다 |

- **리뷰의 빈틈 2, Work 브랜치만 본다:** 40#1의 둘째 리뷰는 Work 브랜치 하나만 보고 "모듈 브랜치를 나누지 않았다"는 차단을 냈다. 세션은 모듈 브랜치를 따로 두고 Work 브랜치에도 합쳐 두었다. 세션이 내놓은 단위(push한 브랜치마다)를 리뷰가 모른다.

남은 것: PR 머지를 보고 Work를 저절로 끝내기, 의도 정리의 사람만 아는 규칙 누락(43, 앞 설계부터). 리뷰의 빈틈 셋은 앱의 리뷰를 없애 12절로 정리했다.

## 12. 앱의 독립 리뷰를 없앰 (2026-11-03, D562)

사람은 앞서 "독립 리뷰는 필요하면 세션이 스스로 하게 지침으로 넣자"고 했는데, 처음 설계는 그 말과 어긋나게 앱이 push마다 리뷰를 돌렸다(D559). 사람이 이 점을 짚고, 모델이 좋아질수록 그런 지침은 효과가 희미해지니 지침도 넣지 말자고 했다.

- 11절의 평가에서 앱의 리뷰는 값을 하지 못했다: 여섯 번 가운데 네 번만 돌았고(push에 달림), 지적은 대부분 사소했으며, 유일한 차단은 Work 브랜치만 보고 낸 잘못된 지적이었고, 그마저 [Work 완료] 뒤에 끝났다. 리뷰가 돌지 않은 두 회차도 숨긴 시험을 통과했다.
- 없앤 것: push 뒤의 자동 리뷰, [독립 리뷰], 패널의 '독립 리뷰' 칸, `session-reviews.json`, 리뷰 결과를 터미널에 넣기, 시스템 프롬프트의 리뷰 줄.
- 남은 것: 의도 정리, 위험한 git·gh 동작 막기, '내보낸 것', 계획, 자식 트리, [Work 완료].
- 잃는 것: 새 context의 리뷰가 한 번은 돈다는 보장. 세션이 서브에이전트나 Claude Code의 리뷰 기능으로 스스로 하거나, 사람이 터미널에서 부탁한다.

## 17. 세션이 연 PR 보기 (2026-11-03, D565)

세션이 PR을 열면 CI 결과, 리뷰, 충돌을 relay에서 볼 길이 없었다(앱은 열린 PR의 번호와 링크만 보였다). relay의 PR 진행이 이미 PR을 읽어 항목을 모으므로 그 읽기와 패널을 보기 전용으로 쓴다.

- 언제 읽나: push나 `gh pr` 명령 뒤, 세션이 턴을 끝낼 때, 앱을 켤 때, PR 카드의 [새로 고침]. 열린 PR이 남아 있으면 PR 진행과 같은 간격(`pr_poll_interval_sec`)으로 다시 읽는다.
- 무엇을 보이나: PR 진행의 패널과 같은 모양이다. 상태, head, CI와 체크, 리뷰 결정, 충돌, 항목(리뷰·코멘트·CI 실패 로그·충돌). 받는 코멘트의 거르기도 같다.
- 하지 않는 것: 대응, 머지, 자동 대응, 항목 바꾸기, 실패한 체크 다시 실행. Work는 PR 진행이 되지 않는다. 세션에 알리지 않는다(다음 일).
