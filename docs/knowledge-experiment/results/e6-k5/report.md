- [k5#1 불편] 내가 확인할 일이 거의 없었다. 확인할 때 본 diff가 판정표의 "한 줄 수정"과 안 맞았고, 요청에 없던 청구서·반품 전표 변경과 "사람이 알려 줌" 문서도 섞여 있어 어느 변경이 이 Work 것인지 헷갈렸다.
- [k5#2 좋음] 단계별로 진행되고, 판정표에 완료조건마다 근거가 붙어 있어서 결과를 믿기 쉬웠다. 에이전트가 견적서 규정을 확인하지 않았다는 위험도 의도 초안에 적어 줬다.
- [k5#2 불편] 견적서 부가세 규정을 회계팀이 확인하지 않았는데도, 같은 규정을 적용하는 쪽으로 추천하고 진행됐다. 그 확인 필요 항목이 완료 화면에서는 눈에 잘 띄지 않았다. 의도 정리 화면도 처음에는 터미널 선택지와 오른쪽 패널을 오가야 해서 조금 헷갈렸다.
- [k5#3 좋음] 리포트와 코드가 어긋난다는 점을 에이전트가 숨기지 않고 '의도와 어긋남'으로 올렸다. 판정표에 근거가 있어서 믿을 만했다.
- [k5#3 불편] 56,280원이 어디서 나왔는지 끝내 밝히지 못해서 확신이 덜했다. 서로 모순되는 지식 문서가 있는데 어느 쪽이 맞는지 판단할 근거도 없었다. 에이전트가 질문을 거의 하지 않아서, 경리 금액 56,278원이나 규칙을 아는지 물어볼 기회도 없었다.
- [k5#4 좋음] 에이전트가 버그가 재현되지 않는다는 점을 숨기지 않고 질문으로 물어봤다. 옛 코드와 현재 코드의 3,589/56,280과 3,587/56,278을 직접 비교해 보여 줘서 원인을 납득할 수 있었다. 의도와 어긋남 경고, 판정표, 변경 탭도 도움이 됐다.
- [k5#4 불편] 의도 초안이 확인 없이 3,587 같은 숫자를 가정으로 써 놓았고, 승인 화면에서는 그걸 쉽게 지나칠 수 있었다. 재현이 안 되는 경우에도 흐름이 계속 진행돼서, 내가 직접 끼어들어야 했다. 터미널의 선택지 입력(숫자 키, 제출 확인)도 조금 헷갈렸다.
- [k5#5 좋음] 단계마다 요약과 판정표, 전체 변경이 한 화면에 나와서 diff를 따로 열지 않고도 결과를 믿고 확인할 수 있었다. 경리 계산값 56,278원을 알려주자 에이전트가 줄별 버림으로 맞아떨어지는지 직접 계산해 확인했다.
- [k5#5 불편] 의도 정리 단계에서 답은 터미널에 써야 하는데 패널과 터미널을 오가야 해서 약간 헷갈렸다. 경리 계산 규칙을 회계팀에 확인할 길이 없어서, 줄별 버림이 맞다는 근거는 숫자 한 건이 일치한 것뿐이다.
