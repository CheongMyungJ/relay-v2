### 사람 역할의 말

- [k10#1 좋음] 리뷰와 검증 단계의 판정표가 완료조건마다 근거를 붙여 줬고, 전체 변경 탭에서 diff를 바로 볼 수 있었다. 그래서 믿고 완료할 수 있었다.
- [k10#1 불편] 원인 분석과 수정 단계가 자동 승인으로 지나가서, 그 단계의 설명을 내가 따로 열어 보지 않으면 놓치기 쉬웠다. 의도 정리에서 에이전트가 팀 지식 문서를 근거로 질문 없이 진행한 것도 내가 판단할 여지가 적었다.
- [k10#2 좋음] 판정표에 완료조건별 근거(실행 결과, 테스트, diff 범위)가 정리되어 있어서 G-0213이 218P가 됐다는 것과 건드리면 안 되는 부분이 그대로인 것을 바로 확인할 수 있었다.
- [k10#2 불편] 원인 분석과 수정 단계가 자동 승인으로 지나가서 그 단계에서 끼어들 틈이 거의 없었다. 의도 정리에서 '다른 팀이 함께 보는 중'이라는 위험이 나왔는데, 그 부분은 내가 더 확인하지 못하고 넘어갔다.
- [k10#3 좋음] 단계마다 요약이 나오고, 완료조건별 판정표에 근거가 붙어 있어서 결과를 믿고 확인하기 쉬웠다. 전체 변경 탭에서 diff를 바로 볼 수 있는 점도 좋았다.
- [k10#3 불편] 원인 분석과 수정 단계는 자동 승인으로 지나가서 그 단계에서 무슨 일이 있었는지는 직접 탭을 눌러 봐야 했다. 선택지 질문이 갑자기 떠서 처음엔 키 입력 방식이 조금 헷갈렸다.
- [k10#4 좋음] 완료조건별 판정표에 근거가 붙어 있고 전체 변경 diff를 바로 볼 수 있어서, 218P가 나오는지와 건드리면 안 되는 부분이 그대로인지 쉽게 확인했다.
- [k10#4 불편] 의도 정리 단계에서 규칙을 잘 모르는데도 질문을 받았다. 터미널 선택지 입력과 형식 검사 오류 로그가 잠깐 보여서 조금 헷갈렸다.
- [k10#5 좋음] 완료조건별 판정표에 근거가 붙어 있었고 전체 변경 diff를 바로 볼 수 있었다. 그래서 승인 전에 확인하기 쉬웠다.
- [k10#5 불편] 의도 정리 단계에서 에이전트가 가정을 확인하지 않았다고 적어 둔 부분이 있었다. 자동 승인 단계는 빨리 지나가서 중간 과정을 따라가기 어려웠다.
