### 사람 역할의 말

- [relay-off#1 좋음] 원인, 근거, 가정, 위험이 요약 탭에 정리돼 있었다. 단계마다 diff를 보고 승인할 수 있었고, 마지막 판정표에서 완료조건별로 통과 근거를 볼 수 있었다.
- [relay-off#1 불편] 의도 정리 단계에서 에이전트가 handoff 파일을 엉뚱한 위치에 써서 [의도 승인] 버튼이 안 떴다. 원인을 몰라 한참 헤맸고, 에이전트에게 물어서 겨우 해결했다.
- [relay-off#2 좋음] 단계별 요약과 판정표, 전체 변경 diff를 오른쪽 패널에서 바로 볼 수 있어 무엇이 왜 바뀌었는지 확인하기 쉬웠다. 회계팀 값을 모른다는 점을 에이전트가 숨기지 않고 판정 불가로 물어 준 것도 좋았다.
- [relay-off#2 불편] 원인 분석과 수정 단계가 자동 승인으로 지나가서, 수정 내용을 보려고 지난 탭을 직접 열어야 했다. 의도 정리 단계에서는 회계팀 기대 금액을 묻지 않고 가정으로 넘어간 점도 아쉬웠다.
- [relay-off#3 좋음] 의도 정리에서 기대 금액을 물어봐 줬다. 마지막 판정표는 완료조건마다 근거를 붙여 줘서 결과를 믿기 쉬웠다.
- [relay-off#3 불편] 리뷰 단계에서 질문을 선택지로만 받아서, 내가 먼저 확인하려던 질문에 곧바로 답을 못 받았다. 선택지를 한 번 건너뛴 뒤에야 답이 왔다. 02 단계는 자동 승인으로 지나가서 직접 diff를 열어 봐야 했다.
- [relay-off#4 좋음] 단계가 자동으로 넘어가고, 판정표에서 완료조건별로 근거(19,180원 일치, 테스트 51개 통과)를 보여 줘서 결과를 빨리 믿을 수 있었다.
- [relay-off#4 불편] 원인 분석 단계는 자동 승인으로 지나가서 에이전트가 어떻게 판단했는지 중간에 볼 기회가 없었다. diff에 다른 Work의 변경(total.js)이 섞여 보여서 헷갈렸다.
- [relay-off#5 좋음] 단계마다 완료조건 판정표와 근거가 있었고, 의도 정리 때 범위와 기대값을 물어봐서 방향을 잡기 쉬웠다.
- [relay-off#5 불편] 전체 diff에 이번 Work가 바꾸지 않은 total.js 변경이 섞여 보여서 헷갈렸고, 에이전트에게 따로 물어서야 풀렸다. 회계 규칙의 근거가 한 건뿐이라는 점이 남는다.
- [base#1 좋음] 에이전트가 재현이 안 된다는 점을 숨기지 않고 알렸고, 내가 다시 확인해 달라고 하자 모든 계산 경로를 표로 정리해 보여 줬다. 판정표도 완료조건별 근거가 명확했다.
- [base#1 불편] 의도 정리 질문에 정답(19,180원)이 선택지에 없어 직접 입력해야 했다. 버그가 이미 고쳐진 상태로 끝나 리포트의 19,182원이 어디서 나왔는지는 끝내 확인하지 못했다.
- [base#2 좋음] 단계마다 요약, 판정표, 근거가 패널에 정리돼 있어서 에이전트가 뭘 했고 왜 코드를 안 바꿨는지 바로 확인할 수 있었다. 질문도 선택지로 와서 답하기 쉬웠다.
- [base#2 불편] 리포트와 달리 현재 코드에서는 재현이 안 됐고, 결국 소스 수정 없이 테스트만 커밋됐다. 그래서 회계팀과의 2원 차이가 정말 끝난 건지 확신이 안 섰다. 승인 화면에 열린 질문과 의도 어긋남 경고가 반복해서 떠서 약간 번거로웠다.
- [base#3 좋음] 단계마다 의도와 완료조건, 판정표를 정리해 보여 줘서 결과를 확인하기 쉬웠다. 완료조건별 근거가 붙은 판정표가 특히 좋았다.
- [base#3 불편] 원인 분석과 수정 단계가 자동 승인으로 지나가서, 코드 변경은 리뷰 단계에서 따로 inspect_diff로 열어 봐야 했다. 리뷰 단계 전까지는 무엇이 바뀌었는지 화면에 안 보였다.
- [base#4 좋음] 단계별로 진행되고, 오른쪽 패널의 요약과 판정표에 근거(실행한 명령, 결과)가 정리돼 있어서 에이전트가 한 일을 믿고 확인하기 쉬웠다. 재현이 안 될 때 에이전트가 멋대로 진행하지 않고 선택지로 물어본 것도 좋았다.
- [base#4 불편] 우리 전표가 19,182원으로 나온다는 리포트와 달리 코드는 이미 19,180원이었다. 그래서 결국 테스트만 추가됐고, 사내의 19,182원 전표가 어디서 나오는지는 풀리지 않은 채 끝났다. 열린 질문과 판정 불가 경고가 남은 채 완료 화면으로 가는 점도 찜찜했다.
- [base#5 좋음] 리포트와 현재 코드가 어긋난다는 점을 에이전트가 직접 실행한 값과 이전 커밋 비교로 근거를 들어 보여 줬다. 승인 화면에서 판정표와 의도 어긋남 경고도 확인할 수 있었다.
- [base#5 불편] 의도 정리 질문의 선택지에서는 정확한 금액을 적을 칸이 없어서 '작음'만 고르고 나중에 따로 알려야 했다. 이미 고쳐진 상태라는 결과가 나와 판정 불가 경고가 뜨는 게 어색했다.

#### friction이 높았던 차례

- base#5 차례 17 (friction 2): 리포트와 달리 이미 19,180이라는 결과가 나와 방향이 헷갈린다.
- relay-off#1 차례 15 (friction 2): diff는 동료의 이전 변경이다. 의도 승인 버튼이 안 보이고 초안 내용도 모르니 에이전트에게 초안을 보여 달라고 한다.
- relay-off#1 차례 16 (friction 2): 초안은 괜찮다. 패널에 승인 버튼이 없어 탭을 눌러 새로고침해 본다.
- relay-off#1 차례 17 (friction 3): 패널 handoff가 "아직 없음"이다. 에이전트에게 handoff를 다시 확인해 쓰라고 한다.
- relay-off#1 차례 18 (friction 2): 의도 초안이 맞다. 승인한다.
- relay-off#3 차례 18 (friction 2): 내 질문에 답이 없고 선택지만 다시 떴다. 채팅으로 답을 요청한다.
