### 사람 역할의 말

- [k2#1 좋음] 단계별로 의도, 원인, 변경 diff, 완료조건 판정표를 한 화면에서 확인할 수 있었다. 내가 아는 사실(경리 값 56,278원)을 물어봐 줘서 완료조건에 반영됐다.
- [k2#1 불편] 열린 질문을 답하지 않고 승인할 때마다 확인창이 또 떴다. 부가세 규칙은 내가 확정할 수 없어서 가정으로 넘어갔고, 회계팀 확인이 남은 채 끝났다.
- [k2#2 좋음] 리뷰 단계에서 버그가 재현되지 않는다고 솔직하게 알려 줬다. 그래서 fix 단계로 되돌려 56,280원의 출처가 옛 코드 계산이라는 것을 확인할 수 있었다. 판정표에 완료조건별 근거가 정리되어 있어 확인하기 쉬웠다.
- [k2#2 불편] 되감기를 하려면 [승인하고 멈춤]을 누른 뒤 [단계 선택]을 거쳐야 해서 흐름이 헷갈렸다. 의도 정리 단계에서 이미 재현 안 될 수 있다는 낌새를 알려 주지 않은 것도 아쉬웠다. 에이전트가 먼저 56,278원이 나오는지 확인했다면 한 바퀴를 아꼈을 것이다.
- [k2#3 좋음] 단계별로 판정표와 근거가 나와서 완료조건이 하나씩 통과했는지 바로 확인할 수 있었다. 원인 단계 요약에 줄별 버림과 줄별 반올림을 비교한 근거가 있어서 믿을 만했다.
- [k2#3 불편] 경리 금액(56,278원)을 처음 질문에서는 적을 곳이 없어서 헷갈렸다. 선택지 2번을 골랐는데도 한 번 더 같은 걸 물었다. 그리고 inspect_diff에 이전 Work 변경이 섞여 나와서, 이번 Work의 quote.js 변경만 보기 어려웠다.
- [k2#4 좋음] 리포트와 코드가 어긋난다는 걸 의도 정리 단계에서 바로 짚어 줬다. 근거도 같이 보여 줘서, 코드를 억지로 고치는 대신 조사 방향을 정할 수 있었다.
- [k2#4 불편] 코드 변경이 0인 채로 끝나는 흐름이라 '완료'가 맞는지 판단하기 애매했다. 판정 불가 항목이 남은 채 완료 화면으로 넘어가는 것도 어색했다.
- [k2#5 좋음] 에이전트가 재현이 안 된다는 사실을 숨기지 않고 질문으로 물었다. 옛 커밋에서 56,280이 나온다는 실험 근거와 판정표에서 "판정 불가"를 그대로 보여 줘서 믿을 만했다.
- [k2#5 불편] 의도 정리 단계에서 "기준 커밋에서 이미 다르게 나온다"는 말이 모호했다. 그리고 단계 탭을 누르려다 [변경] 탭을 잘못 눌러서, 승인 전에 무엇을 보고 있는지 잠깐 헷갈렸다.
