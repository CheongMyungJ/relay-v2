# relay-v2 확인 기록

구현 마일스톤마다 실제 `claude` 흐름 시험([실제])과 사람의 실기 확인([실기]) 결과를 적는다. 확인할 항목은 `docs/implementation.md` 7절, 확인 방법은 8절을 따른다(I30).

## 기록 규칙

- 확인할 때마다 해당 마일스톤 표에 한 줄씩 더한다.
- 날짜, 앱 커밋, Claude Code 버전, OS를 적는다.
- 러너 결과는 예비 확인이다. OS 칸에 러너 이미지를 적는다(D93).
- [실제]의 메모에는 task마다 형식 오류 되돌림 횟수와 걸린 시간을 적는다(8.4).
- 실패한 항목은 메모에 무엇이 어떻게 달랐는지 적는다.

### M11 [실기] 목록

Windows 10/11 PC에서 설치한 앱과 실제 `claude`, 시험용 레포(`CheongMyungJ/relay-v2-test`)로 본다. PR과 브랜치는 끝나면 치운다. 결과는 위 표에 한 줄로 더한다.

1. 설정 화면: "자동 대응 (PR 진행)" 절에 대응 자동 시작(기본 꺼짐)과 자동 대응 라운드 상한(기본 3)이 보이고, 자동 승인 목록에 "PR 대응"이 있다. 상한에 0이나 21을 넣으면 저장하지 않고 오류를 보인다.
2. 새 Work 대화상자: "이 Work의 자동 대응 (PR 진행)"을 펼치면 대응 자동 시작을 "앱 설정 따름 / 켜기 / 끄기"로 고른다. "이 Work의 자동 승인"에 "PR 대응"이 있다.
3. PR 진행인 Work의 액션 바에 [Work 설정]이 있다(D209). 열면 "자동 대응 (PR 진행)"과 PR 대응의 자동 승인을 바꿀 수 있고, 저장하면 PR 패널의 자동 대응 줄이 "(이 Work)"로 바뀐다. 이미 받은 새 항목이 있어도 켜는 것만으로는 대응 task가 시작하지 않는다(D210).
4. PR 패널의 대응 절 맨 위: "대응 자동 시작 켜짐(…) · 자동 승인 켜짐/꺼짐(…) · 사람 손 없이 이어진 라운드 r/상한"이나 꺼진 안내가 보인다.
5. 자동 시작: 켠 Work의 PR에 소유자 코멘트를 달면(또는 CI가 실패하면) 다음 읽기에서 대응 task가 사람 손 없이 시작하고, OS 알림 "PR #n: 자동 대응 시작 — 라운드 r, 새 항목 k개"가 온다. "대응 거리 n개가 들어옴" 알림은 오지 않는다. 대응 task의 머리 띠 이유는 "자동 대응"이다.
6. PR 대응의 자동 승인: 대응 task의 턴이 끝나면 승인 화면에 카운트다운과 [취소]가 보이고 알림 "… 초 뒤 자동 승인"이 온다. [취소]하면 카운트다운이 없어지고 까닭이 보이며 사람이 [승인]한다. 그대로 두면 자동 승인으로 push하고 답글을 게시한다(라운드 기록과 PR의 답글).
7. 상한: 상한을 1로 두고 자동 라운드 하나가 끝난 뒤 새 코멘트를 달면 대응 task가 시작하지 않고, 알림 "PR #n: 자동 대응 멈춤 — …", 사이드바 배지 "자동 대응 멈춤", PR 패널의 강조된 멈춤 안내가 보인다. [대응 시작]을 누르면 셈이 0으로 돌아간다(패널의 r).
8. 재시작(D159): 자동 시작을 켠 채 앱을 끄고 PR에 코멘트를 단 뒤 다시 켜면 항목만 보이고 대응 task가 시작하지 않는다. 그 뒤 새 코멘트가 들어오면 둘을 함께 넣어 시작한다.
9. 닫힌 PR(D208): 대응 task가 승인 대기일 때 GitHub에서 PR을 닫고 앱이 읽기 전에 [승인]하면 push와 답글 게시를 하지 않고 "PR이 열려 있지 않아(닫힘) push·게시하지 않음"이 보인다. 다시 열고 [새로 고침]한 뒤 [다시 시도]하면 push하고 게시한다.
