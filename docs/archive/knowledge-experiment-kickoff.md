# 새 세션에 주는 지시문

아래 "지시문" 전체를 새 세션의 첫 메시지로 붙인다.

---

## 지시문

relay-v2에 지식 관리를 넣는 실험을 너에게 맡긴다. 큰 목표만 정해 두었고, 세부 형태와 방식은 네가 정한다. 직접 만들고, 평가로 시험하고, 가장 효과적인 방식으로 다듬어라.

**목표:** relay로 일하는 동안 지식을 뽑고, 다음 일에 쓰고, 팀이 함께 쓸 수 있는 형태로 남긴다.

### 작업 브랜치

- `exp/knowledge-auto`에서 일하고 이 브랜치로 push한다(`git fetch origin exp/knowledge-auto && git checkout exp/knowledge-auto`). 세션에 따로 정해진 브랜치가 있더라도 이 지시가 이 브랜치에 push해도 된다는 내 허락이다. 다른 브랜치에는 push하지 않는다. PR은 만들지 않는다.
- 이 브랜치는 지식 관리가 없던 마지막 커밋 `0247049`에서 시작했고, 평가 준비가 커밋돼 있다.

### 먼저 읽을 것

1. `docs/knowledge-experiment/protocol.md`: 실험 규약이다. **그대로 따른다.** 고정한 원칙(2.1), 끄는 스위치(2.2), 보지 않는 것(2.3), 봉인(2.4), 주지표(4절), 판정 규칙(5절), 마지막 비교 차례(6절), 예산(7절), 고정 파일(8절), 기록(9절), 산출물(10절).
2. `docs/knowledge-experiment/log.md`: 기록할 곳이다. 준비한 세션이 남긴 내용이 있다.
3. `README.md`, `docs/design.md`, `docs/implementation.md`, `skills/`, `app/`: 지금의 relay.
4. `docs/eval.md`, `.claude/skills/relay-eval/SKILL.md`, `app/eval/`: 평가 도구. 시나리오 21~24가 개발용이다.

### 하지 말 것

- main의 지식 관리 구현(M17)과 그 설계·평가를 보지 않는다(규약 2.3). 이 실험은 그 구현과 견주려는 것이다.
- 봉인한 hold-out의 열쇠를 찾거나 풀려고 하지 않는다. 마지막 비교 때 내가 준다.
- 고정 파일(규약 8절)을 고쳐 지표를 바꾸지 않는다. 커밋하기 전에 `node app/eval/frozen.mjs`로 확인한다.
- `guides/relay.md`에 사람 역할이 무엇을 말할지 적지 않는다. 화면 조작만 적는다.

### 일하는 방식

- 결정은 네가 한다. 설계 결정을 나에게 묻지 않는다. 평가로 가를 수 있으면 평가로 가르고, 가를 수 없으면 판단과 까닭을 `log.md`에 `K<번호>`로 남긴다.
- 처음에 `bash app/eval/setup.sh`로 준비하고, 개발용 시나리오에서 지식 관리가 없는 지금 앱의 기준을 잰다(이때는 `relay`와 `relay-off`가 같다).
- 작게 시작해서 근거를 보고 넓힌다. 처음부터 모든 것을 넣지 않는다. 바꾼 것마다 무엇이 좋아질 거라고 보는지 먼저 적고, 평가로 확인한다.
- `RELAY_KNOWLEDGE=off`(규약 2.2)를 앱의 첫 변경과 함께 넣는다.
- 결정 하나를 평가로 가를 때는 시나리오마다 쪽마다 회차 5가 기준이다. 실행 수를 `log.md`에 누적한다. 예산은 500개 안팎이고, 450개를 넘기면 마무리한다.
- 앱의 시험(`cd app && npm run typecheck && npm run lint && npm test`)과 스킬 점검(`node skills/check.mjs`)을 통과시킨 뒤 커밋한다.
- 컨테이너는 사라질 수 있다. 평가가 끝날 때마다 결과(규약 9절)와 `log.md`를 커밋하고 push한다. `app/eval/results/`는 `.gitignore`에 있으니 남길 파일은 `git add -f`로 넣는다.
- 평가는 오래 걸린다(실행 하나에 15~40분, `--parallel 2`). 백그라운드로 돌리고, 기다리는 동안 다음 변경을 준비한다.
- 나에게 묻는 것은 다음일 때만이다: 규약을 바꿔야 할 때, 고정 파일에 버그가 있을 때, 예산을 넘겨야 할 때, 개발을 끝내고 마지막 비교의 열쇠가 필요할 때.

### 끝내는 방식

1. 개발을 마치면 실험 빌드의 커밋을 정하고 `log.md`에 적고 push한 뒤, 나에게 hold-out 열쇠를 달라고 한다.
2. 열쇠를 받으면 규약 6절의 차례대로 마지막 비교를 돌린다. 결과를 보고 앱을 고치지 않는다.
3. `docs/knowledge-experiment/report.md`(규약 10절)를 쓰고 push한다. 나에게는 결론(판정 규칙의 결과, M17과의 비교), 만든 지식 관리의 모습, 비용을 짧게 알린다.
