# `root-cause` — 원인 확정

## 목적

증거로 뒷받침되는 **하나의 원인**을 확정하고, 기각한 가설을 근거와 함께 남긴다. 수정 방향을 제안한다.

## 입력 (context.md)

intent, decisions, rejected-log, prev-handoff(evidence), `evidence/evidence.md`(path), 고정된 재현 테스트 정보(repro-lock 조각: 파일, 고정 커밋, 실패 출력 끝부분), gate-policy, next-options.

## 결정 지점 (질문 예산: 최대 2개)

| # | 결정 | `requires_human` | 언제 |
|---|---|---|---|
| 1 | 가설 채택: 이 원인으로 확정해도 되는가 (근거 요약과 함께) | ✅ | 항상 |
| 2 | 수정 방향: 후보가 여럿이면 어느 쪽인가 (추천 포함) | ✅ | 방향 후보가 2개 이상이고 트레이드오프가 있을 때만 |

## 절차

1. evidence.md와 재현 테스트를 읽는다. 재현 테스트가 **올바른 이유로 실패하는지** 먼저 확인한다. 아니라면 `recommended_next: evidence`로 되돌리고 이유를 적는다.
2. 가설 목록을 만들고, 각각 **반증 실험**을 설계해 실행한다(로그 추가, 값 바꿔 보기, 좁은 테스트). 실험용 코드 변경은 커밋하지 않고 되돌린다.
3. 살아남은 가설 하나를 원인으로 정리한다. 증거가 부족하면 확정하지 않고 `recommended_next: evidence`.
4. 영향 범위(같은 원인을 공유하는 다른 경로)를 확인한다.
5. 수정 방향을 1~2개 제안한다. 방향이 intent의 비목표나 제약과 충돌하면 `intent_deviation`.
6. 결정 지점을 묻고 반영한다.
7. `_close`.

## 완료조건

- 원인이 한 문장으로 적혀 있고, 그 원인을 뒷받침하는 증거(실험과 결과)가 1개 이상 있다.
- 기각한 가설마다 기각 근거가 있다(`rejected`와 rca.md 모두).
- 수정 지점(파일, 함수)과 영향 범위가 적혀 있다.
- 결정 지점 1의 답이 `decisions`에 있다.

## 산출물 템플릿 — `rca.md`

```markdown
# 원인 분석: <intent 제목>

## 원인
<한 문장>

## 근거
| 실험 | 결과 | 의미 |
|---|---|---|

## 기각한 가설
| 가설 | 반증 | 근거 |
|---|---|---|

## 수정 지점과 영향 범위
- 수정 지점: `src/...:<줄>`
- 같은 원인을 공유하는 경로: 

## 수정 방향
1. (추천) ...  — 장단점
2. ...

## 재현 테스트 확인
- 고정된 테스트가 원인을 정확히 겨냥하는가: 예/아니오 + 이유
```

## handoff 확장

없음. `recommended_next`는 보통 `null`(기본: fix) 또는 `evidence`.

## 하지 말 것

- 수정을 커밋하지 않는다. 실험 변경은 모두 되돌린다(승인 시 `tree:clean`이 아니면 경고가 뜬다).
- 재현 테스트 파일을 고치지 않는다. 테스트가 틀렸다고 판단되면 그 판단을 적고 evidence로 돌려보낸다.
