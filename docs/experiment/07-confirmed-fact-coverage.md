## 변경과 버린 방식

`skills/_common.md`의 지식 단락을 재구성했다. 코드 변경 단계는 커밋 전 요청·intent·사람 답변·관측·앞 task의 전달 근거를 기존 공유 기록과 대조한다. 변경의 정당성뿐 아니라 새 확정 사실의 누락도 확인한다. 코드 범위나 완료조건으로 학습 범위를 제한하지 않는다. 미래에 적용될 확정 업무 규칙은 적용 조건·확인 근거와 함께 공유하되 구현 완료로 표시하거나 이번 코드 범위를 넓히지 않는다. 중요한 차이와 근거 또는 변경 없음의 이유는 기존 task 산출물에 간결히 남긴다.

`skills/verify/SKILL.md`는 원요청과 사람 답변·앞 handoff를 검토 입력으로 명시한다. 작성자의 변경 요약과 별개로 최종 공유 기록의 전달 여부를 확인한다. 지식 diff가 없거나 코드 완료조건이 모두 통과해도 누락 검토를 생략하지 않는다. 누락은 리뷰 지적이며 정정은 기존 복귀 절차로 코드 변경 단계에 돌려보낸다. 사람이 지적을 골라도 verify가 지식을 직접 작성하지 않는다. 운영 설명도 같은 기준으로 통합했다.

중복된 불변·정정·출처 안내를 합쳤고 특정 업무 예시를 운영 지침에서 제거했다. 공통 원문은 11,434 → 10,916자(-518), verify 원문은 11,498 → 12,001자(+503)로 합계 15자 줄었다. 가장 큰 verify·refactor 조립본은 19,009 → 18,994자이며 기존 Claude 어림은 4,749로 목표 5,000 안이다. 이는 실제 pinned Codex 토큰 수나 비용 절감 측정이 아니다. 모든 단계에 새 원장이나 후보 검토 절차를 추가하지 않았다.

채택하지 않은 방식:

- handoff만 충실하게 쓰기: 이번 Work의 다음 task와 새 팀원의 clone/Work 전달 경로가 다르므로 결함을 해결하지 못한다.
- 코드 수정 대상과 같은 사실만 공유하기: 확정된 미래 규칙을 구현 비목표와 함께 버린다. 기록과 구현 범위를 구분했다.
- 추가된 문장의 정당성만 리뷰하기: 수정 전 verify가 이미 그 검토를 통과했다. 원근거에서 최종 문서로의 누락 검토가 필요하다.
- 모든 요청·계획·통과 기록을 공유하거나 별도 전수 목록 만들기: 관리 비용과 중복을 늘린다. 재사용성·근거·실질적 차이를 충족하는 사실만 기록한다.
- fixture 문구/값/파일명에 맞춘 조건, 자동 의미 판정기, 별도 UI·DB·검색 서비스: 일반 결함에 필요하지 않으며 만들지 않았다. Git 출처와 큰 문서의 고정 스냅샷 조회는 그대로다.
