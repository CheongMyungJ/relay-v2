# 프로젝트 지식 운영

Relay는 새 task 시작 때 해당 Work worktree의 HEAD에 있는 `.relay/knowledge.md`를 읽어 context.md에 제공한다. Git blob ID가 출처다. 개인 RELAY_HOME에서 검색하거나 이전 대화를 복사하지 않는다. 문서가 없으면 기존 흐름 그대로 진행한다. 일반 파일만 허용하고 12,000바이트를 넘으면 전체를 제외한다. 이미 실행 중인 task의 컨텍스트는 바뀌지 않는다.

코드를 고치는 스킬은 사람이 확인한 재사용 업무 사실만 정리한다. 각 사실에 적용 범위, 규칙, 사람 답변 발췌, 확인 날짜, Work/task 출처를 쓴다. 모르는 사실은 질문하고 AI 추정은 공유 사실로 만들지 않는다. 변경한 지식 문서는 코드와 같은 diff에서 검토한다. 사람이 산출물과 diff를 읽고 잘못된 요약을 터미널에서 수정 지시한 뒤 다시 검토·승인한다. 별도 자동 승인이나 게시 절차는 없다.

공유하려면 기존 프로젝트 Git 절차로 Work 브랜치를 검토하고 기준 브랜치에 merge한다. 다른 팀원은 clone/pull하고 새 Work를 시작한다. 앱 저장소를 복사할 필요가 없다. 실험의 로컬 bare 원격은 Git 전달만 검증하며 실제 GitHub PR 게시는 하지 않는다.

현재 요청과 intent가 공유 문서보다 우선한다. 규칙 변경이 확인되면 기존 활성 규칙을 교체하고 무엇을 대체했는지 적는다. 무관한 항목은 무시한다. 사용한 사실의 출처와 충돌을 task 산출물에 기록한다. 문서 삭제를 커밋하면 이후 task에 제공되지 않는다. 문서만 지워도 이미 시작한 task의 스냅샷은 남으므로 해당 task는 재시작하거나 명시적으로 정정해야 한다.

제약: 적용 범위·노후화·정확성은 모델과 사람이 판단한다. 앱은 내용의 진위를 자동 인증하지 않는다. 작은 문서 전체를 매 단계에 제공하므로 토큰 비용이 생긴다. 다수 팀원과 큰 문서에서 효율적이라는 증거는 없다. 추출이 누락되거나 요약이 잘못될 수 있으며, 승인 자체가 미래 모든 작업의 적합성을 보장하지 않는다. 실제 사람의 화면 사용성은 이번 headless 서비스 실험으로 검증되지 않는다.
