# 개발 회차 1 — 작은 공유 문서

시작: 2026-10-03, 기준 02470492e9a0429322aaf9f227db8362c13bad2c.
최초 quota: 94% 잔여. 33%에서 모델 중단, 50%에서 개발 예산 재검토.

가설: 사람이 확인한 업무 규칙을 코드와 함께 검토·커밋하는 작은 문서에 보존하고 Relay가 다음 task의 context.md에 제공하면, 별도 개인 캐시 없이 재설명과 재탐색을 줄일 수 있다.

변경: `.relay/knowledge.md`의 HEAD Git blob을 실제 WorkRunner가 읽어 모든 새 task 컨텍스트에 출처와 함께 제공한다. 미커밋 파일은 제공하지 않는다. 12,000바이트 초과 문서는 잘라서 의미를 바꾸지 않고 제외 사유를 알린다. 현재 요청/intent 우선, 적용 범위 확인, 충돌 질문, 사용 출처 기록을 지시한다. 코드 수정 단계에서만 사람이 직접 확인한 재사용 사실을 문서로 정리하고 기존 diff 검토를 활용한다. 추가 UI/분류/벡터 검색/자동 후보 DB는 첫 가설에 필요하지 않아 구현하지 않는다.

조건: 공개 dev fixture, 실제 relay-session.mjs 서비스·Codex PTY·훅·MCP, CODEX_BIN의 pinned gpt-6.1-sol/medium. Work 1 평균 수정 후 로컬 bare 원격과 새 clone/RELAY_HOME으로 Work 2 중앙값 수정. 같은 평균 코드를 지닌 문서 없는 clone에서 Work 2를 한 번 더 실행하여 문서 효과를 탐색한다. 문서 없는 비교도 새 구현을 쓰되 입력 문서가 없으므로 추출 지침 비용은 동일하게 적용된다. 기존 대조군 구현은 읽지 않는다.

실제 모델, 질문, 승인, 산출물 검토, 정답 검사와 사용량은 별도 결과에 기록한다. dry/단위 테스트는 통합 효과 증거가 아니다. 독립 최종 평가는 상위 진행자가 담당하며 이번 공개 사례로 우월성을 주장하지 않는다.

초기 harness 실패: 첫 exec를 tty 없이 시작하여 stdin이 닫혔고 Work를 만들지 못했다. 이 실행(work1)은 모델 성과에 포함하지 않는다. 새 디렉터리(work1-live)에서 tty로 다시 시작했다.
