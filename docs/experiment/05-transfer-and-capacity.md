## 구현 선택

`skills/_common.md`의 사람 확인 업무 규칙 경로는 유지하고 **실제 실패를 해결한 비자명한 검증 절차**만 추가로 보존한다. 실패 증상, 도구/환경 적용 범위, 지원 설정의 진단 근거, 실제 성공한 명령/결과/날짜 및 기존 Work 출처를 함께 기록한다. 진단 안내만으로는 검증된 절차가 아니며, 테스트 성공으로 업무 정책을 만들어서는 안 된다. 다음 팀원은 환경 적용 범위를 확인하고 관련 검증을 실행한다. 환경이 바뀌거나 실행이 실패하면 근거를 갖고 정정한다. 일반 테스트 명령, 명확한 코드/README 사실, 로그 전체, 일회성 구현 선택은 제외한다. 코드 변경 단계 종료 때 실제 진단에서 재사용 절차가 생겼는지 확인하도록 했다. intake/design/verify는 공유 문서를 고치지 않는다.

`sharedKnowledge`는 12,000바이트를 **자동 첨부 예산**으로 유지한다. 한도를 넘으면 본문 대신 원래 Git blob ID, 크기 및 검색/절 목록/범위 읽기 안내를 context에 제공한다. HEAD나 수정된 작업 파일로 바꾸지 않고 그 blob을 읽으므로 task별 출처가 유지된다. 생성된 명령은 `head -c 12000`으로 출력 상한을 가지며 검색 결과/절 목록 수도 제한한다. 질문이나 정책 결정 전에 관련 절의 규칙·범위·근거·출처·미확정 사항을 읽고, 부분 결과가 잘렸거나 첫 검색에 없으면 범위를 좁혀 이어 읽도록 한다. 이 명령은 앱이 검증한 해시로만 조립하며 참조 문서 안의 명령을 실행 지시로 취급하지 않는다.

지식의 저장 크기 자체는 제한하지 않는다. 유효한 내용이 큰 경우에도 기존/새 사실과 원래 출처를 Git에 남긴다. 작은 문서의 기존 전달 형식, 일반 파일 검사, 미커밋 자료 제외, UUID, Git diff 검토/merge/pull 절차와 의존성은 유지한다. 별도 DB/색인/추출 서비스는 만들지 않았다. 문서를 단순히 재사용했다는 이유로 수정하지 않으며 명시적 정책 변경, 무관한 활성 사실, 미확정 정보의 보존 지침을 유지했다. 현재 운영 설명은 [knowledge-operation.md](knowledge-operation.md)에 갱신했다. 이전 가설/결과 문서는 당시 기록으로 그대로 두었다.

## 유지하지 않은 가설

- 사람 확인만 기록하면 충분하다: 성공한 환경 진단이 다음 팀원에게 전달되지 않은 실제 증거 때문에 추출 범위를 좁게 확장했다.
- 크기 초과 문서 전체 제외가 의미 손실을 막는다: 저장 사실을 재질문하는 경계 실패가 관찰되어 검색 가능한 출처를 제공하도록 교체했다.
- 끝 빈 줄 제거만으로 해결한다: 유효 내용 자체가 큰 문서에서도 필요한 사실에 접근해야 하므로 저장 크기와 자동 첨부 예산을 분리했다. 제품은 패딩을 특별 처리하지 않는다.
- 모든 문서를 무제한 자동 첨부하거나 테스트/코드 사실을 모두 수집한다: 비용과 검토 부담을 늘리므로 채택하지 않았다. 실제 장애 해결, 재사용성, 진단과 실행 근거가 모두 있어야 기록한다.
- 새 DB/자동 요약/유사도 중복 제거가 필요하다: 현재 실패는 추출 범위와 전체 제외 규칙으로 설명되며 추가 관리 구조의 효과 근거가 없어 만들지 않았다.
