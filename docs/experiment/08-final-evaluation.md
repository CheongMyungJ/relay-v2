# Relay 지식관리 실험 — Git 공유 지식과 실제 Codex 검증

채택한 방식은 Git으로 공유하는 작은 지식 문서와 기존 코드 검토 흐름의 결합이다. 실제 gpt-6.1-sol / medium으로 구현하고 반복 검증하면서, 도구 절차의 미전달·큰 문서의 전체 제외·같은 실행 이력의 누적·미래 업무 규칙의 누락을 발견해 수정했다. 재설명 감소와 새 작업으로의 사실 전달은 확인했지만, 정확도 향상이나 전체 시간·토큰 비용 절감은 입증하지 못했다.

출발점은 지식관리 전 0247049, 비교 대상은 기존 M17 aa39d16이다. 마지막 앱·스킬 평가 소스는068cc27이다. 다섯 번의 실제 Codex 구현 실행과 버전별 비교·회귀를 구분해 기록한다. 최종 후보의 새 사례4Work와 공개 회귀2Work를 완료했다. 최종 절차 사례에서는 과잉 기록이 남아 있음을 확인했다.

## 현재 구현

프로젝트 Git의 `.relay/knowledge.md`에 재사용 가치가 있는 확인 사실을 남긴다. 사람의 업무 규칙과 실제 실패를 해결한 검증 절차를 구분하고, 범위·근거·날짜·Work 출처를 기록한다. 코드와 같은 diff에서 검토하고 Git merge/pull로 팀에 전달한다. 새 task는 커밋된 스냅샷을 참고하며 현재 요청과 승인된 의도가 우선한다. 일회성 작업 범위, 명확한 코드/README 사실, 추측은 지식으로 누적하지 않도록 지침을 둔다. 다만 마지막 절차 사례에서 일회성 변경 제외 범위를 지속 정책처럼 기록한 과잉 추출이 관찰됐다. 의미 판단은 완전히 해결되지 않았다.

12,000바이트 이하는 자동 제공하고, 이를 넘으면 같은 Git blob의 검색과 필요한 줄 범위 읽기를 안내한다. 12,000은 자동 첨부 예산이며 저장 제한이 아니다. 유효한 사실을 용량 때문에 버리지 않는다. 무관한 활성 규칙과 미확정 사항을 보존하고, 명시적으로 바뀐 규칙은 대체 근거를 남긴다. 별도 DB·검색 서버·지식 검토 UI는 추가하지 않았다.
