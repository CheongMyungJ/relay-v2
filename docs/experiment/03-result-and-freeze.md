# 회차 1 결과와 구현 동결

## 선택

동결 후보는 **작은 Git 공유 문서 + 실제 Relay task 컨텍스트 제공 + 기존 변경 검토**다. 코드와 스킬 구현은 913d368에 있다. seed는 커밋 전 working tree에서 시작했으며 그 서비스 번들에는 뒤에 추가한 blob ID 방어 검사가 없었다. seed intake의 빈 중복 제목은 fix 전에 정리했다. 일반 blob 경로의 동작은 같지만 동일 커밋 실행이라고 표시하지 않는다. 두 후속 비교 서비스는 913d368의 app/skills로 새로 시작했다. 이후 커밋은 실험 기록뿐이며 app/skills 트리가 동일하다. 이번 실행에서 모델 Work는 3개, 서로 다른 실제 Codex 세션은 9개였다. 지정 gpt-6.1-sol / medium 외 모델은 사용하지 않았다. 독립 최종 평가는 수행하지 않았고 상위 진행자에게 넘긴다. 자동으로 다음 개발 회차를 실행하지 않는다.

확인된 효과는 규칙 전달과 확인 질문의 구체성이다. **시간·비용 우월성과 실제 사람의 관리 부담 감소는 입증되지 않았다.** 이 후보를 더 복잡하게 만들 근거가 없어 별도 후보 DB, 분류법, 검색 인덱스, 검토 UI를 추가하지 않는다. 이는 그 방식들을 실험해서 열등하다고 판정한 것이 아니다.

## 실제 조건과 정답

공개 dev fixture의 평균 Work 완료 후, 검토한 코드·문서를 로컬 bare 원격에 공유했다. 새 clone/새 RELAY_HOME/새 세션에서 중앙값 Work를 수행했고, 문서만 제거한 다른 clone에서 같은 요청을 순차 실행했다. 두 입력 clone의 src/test 트리는 동일했다. 문서 없는 비교도 같은 후보 구현과 추출 지침을 쓰는 입력 절제 비교이며, 별도 기존 대조군 구현과의 비교는 아니다. 실행 순서 효과를 통제하지 않은 각 1회 탐색 결과다.

최종 worktree의 별도 복사본에서 공개 oracle을 실행했다. 평균 seed 6/6, 두 중앙값 Work 각 6/6 및 평균 회귀 각 6/6 통과. 실제 fixture npm test도 모두 통과(공유형 18개, 문서 없는 경우 15개). 두 후속 작업의 최종 src Git 트리도 동일하다. 모델이 만든 테스트 개수 차이를 정확도 차이로 해석하지 않는다. 기존 report/average 테스트와 다른 집계 구현은 보존됐다. 기존 잘못된 평균은 같은 공개 oracle의 6개 중 5개 실패했다. 중단·인증·모델·harness 실패를 정답으로 대체하지 않았다.

공유형은 질문 1개와 답변 51문자가 줄었지만 대화 왕복은 줄지 않았다. 총 토큰은 약 0.7%, 벽시계는 6초 적었다. 이 차이는 단일 실행의 모델 변동, 산출물·테스트 구성과 운영자 대기에 비해 작아 효율 개선의 증거로 삼지 않는다. 비캐시 입력은 공유형이 8,980토큰 더 많았다. 캐시와 비캐시를 같은 비용으로 합산해 비용 절감이라고 하지 않는다. 요금 정보가 없어 달러 값은 null이다.

호출 수는 exec 등 최상위 Codex 호출 수다. 내부 병렬 호출 수나 낭비 탐색 분류가 아니다. 두 실행 모두 패키지·대상 코드·테스트·원인 재현을 확인했으며 이는 필요한 검증이다. 같은 업무 규칙을 다시 질문한 증거는 있으나 코드 읽기 횟수만으로 불필요한 재탐색 감소를 입증하지 않는다.

## 추출·검토·수정·공유 부담

967바이트 seed 문서를 실제 수정 단계가 생성했다. 비용은 seed 전체 526초·658,834토큰에 포함했으며 코드 수정과 같은 턴에 묶인 추출의 한계 비용은 분리하지 못했다. seed에서 문서 포함 diff를 검토했다. 공유형 후속에서는 기존 문서 3행을 수정해 중앙값 적용 확인을 남겼고, 문서 없는 후속에서는 확인한 규칙을 새 8행 문서로 다시 정리했다. 이 문서 작업도 위 실행 비용과 diff 검토에 포함됐다. 추가 독립 지식 승인 단계는 없다.

review 명령부터 승인까지 운영자 구간은 seed 합계 22.043초, 공유형 47.876초, 문서 없는 경우 33.917초다. 문서만의 검토 시간이 아니며 상위 Codex가 운영한 시간이다. 이 숫자를 실제 사람의 인지·관리 부담으로 환산하지 않는다. 실제 사람 UI 시험은 하지 않았다.

Git 전달은 로컬 bare push/clone에서 검증했다. 최초 전달 포함 exec wall time은 0.557초 이하였지만 검증 실패와 재수리가 발생해 정확한 공유·수리 비용은 분리 측정되지 않았다. 실제 GitHub PR 게시, 네트워크 원격 운영, 다수 팀원의 협업은 검증하지 않았다. 원격 push/PR 게시 및 candidate main 변경은 하지 않았다.

## 반증과 수정 선택

- “문서가 있으면 후속 질문이 없어질 것”은 반증됐다. `별도 보고서`와 `센서 관측`의 범위 차이 때문에 모델이 적용 확인을 물었다. 질문을 없애려고 범위를 추측하도록 바꾸지 않았다.
- “작은 문서가 곧바로 실행 시간·비용을 줄일 것”은 근거가 부족하다. 특히 비캐시 입력 증가를 숨기지 않는다. 더 큰 검색·추출 구조를 추가할 근거가 없다.
- 문서에 이전 Work의 평균 전용 구현 범위가 섞여 있었다. 후속 모델이 공통 규칙을 유지하며 이를 정리했다. 장기 업무 규칙과 한 번의 작업 범위를 혼합하는 문서 작성은 유지 부담을 만들었다. 앱에 복잡한 자동 정리기를 추가하지 않고 기록·제약으로 남긴다.
- clone별 Work/task ID가 같은 값으로 재사용되어 문서의 사람 답변 출처만으로 프로젝트/clone을 고유하게 추적하기 어렵다. Git blob과 답변 근거는 남아 있지만 장기 감사성을 입증하지 않았다. 다음 실험에서 출처 표시 개선이 필요한지 확인한다.

이번 회차에서 만들어 놓고 제거한 DB나 UI는 없다. 최소 구조로 가설을 검증했으며, 불확실한 비용 절감을 이유로 확대하지 않는 것이 이번 선택이다.

## 실패와 증거

초기 tty 없는 서비스 실행은 stdin이 닫혀 Work를 만들지 못했다. 새 run에서 재시작했으며 성공 표본에 넣지 않았다. 전달 검증에서 다른 clone에 없는 커밋을 git diff로 참조한 오류는 두 clone의 src/test 트리 ID 비교로 수정했다. 실제 모델 Work 3개는 모두 완료했으며 force, 형식 오류 무시, 재촉은 0회였다. 수정 전 재현 테스트 실패 및 AGENTS 파일이 없어 rg가 반환한 종료 코드 1은 모델/인증 실패와 구분된다.

근거는 [results/dev-01.json](results/dev-01.json), [공유 컨텍스트 발췌](results/shared-context-excerpt.md), [seed 문서](results/seed-knowledge.md), [후속 수정 문서](results/shared-knowledge-after-followup.md)에 보존했다. 원시 controller·events·PTY·산출물·정확히 매칭된 세션 로그 경로는 JSON 안에 있다. 각 세션의 모델/effort/누적 토큰을 검증했고 동일 세션의 중간 누적 사용량을 합산하지 않았다.

저장소 검사: 타입·lint·포맷·스킬 검사 통과. unit/adapters/flow 테스트 883개 통과, 3개 건너뜀. 이 테스트에는 가짜 CLI 흐름이 포함되며 실제 효과 증거와 구분한다. 모델 효과의 근거는 real 모드 Work와 공개 oracle 결과다. 첫 측정은 주간 잔여량 94%, 종료는 90%였다. 50% 검토와 33% 중단 기준은 도달하지 않았고 wrapper/watcher/manifest/QUOTA_STOP은 변경하지 않았다. 상위 구현 Codex의 비용은 Work 토큰 합계에 포함되지 않으며 주간 quota 변화와 구분한다.

## 다음 선택

[재현 명령과 JSON-lines 운영 절차](reproduce.md)를 사용한다. 상위 진행자는 동결 구현에서 독립 최종 평가를 수행한다. 규칙 변경, 무관한 지식, 사람만 아는 추측하기 어려운 규칙, 실제 팀 공유, 큰 문서 및 반복 작업에서 질문 감소가 누적 추출·수정·검토 비용을 상쇄하는지 확인해야 한다. UI 신뢰와 관리 부담은 사람 시험이 필요하다. 독립 평가에서도 이익이 없으면 자동 컨텍스트 제공을 제거하거나 문서 유지 자체를 줄이는 선택을 열어 둔다.
