## 구현과 제거한 가설

변경은 `skills/_common.md`, `skills/verify/SKILL.md`, [운영 설명](knowledge-operation.md)으로 한정했다. Git 전달·UUID 출처·큰 문서의 고정 blob 검색 구현은 변경하지 않았다.

기존의 “실제 실패를 해결한 절차를 기록” 조건을 **새로 배운 절차 또는 기존 지식의 변화**로 좁혔다. 공유 문서를 수정하기 전에 기존 커밋의 관련 기록과 비교하여 다음 팀원이 새로 배우거나 다르게 판단·실행할 내용과 근거를 task 산출물에 남긴다. 변화가 없으면 공유 문서를 바이트 단위로 유지한다. 같은 절차의 새 출처·날짜·기준 커밋·테스트 수·반복 실패·통과는 task의 실행 근거이며, 공유 절 추가·원날짜 갱신·동일 재사용 후보 생성을 허용하지 않는다. 별도 저장소나 승인 화면을 만들지 않고 기존 산출물과 handoff를 사용한다.

현재 적용 조건을 실제 확인한 뒤 알려진 절차로 필요한 검증을 실행한다. 도구 해시 일치만으로 가변 상태까지 같다고 추측하지 않는다. 진단이 적용 확인에 필요하거나 근거 부족·충돌·적용 가능한 절차 실패가 있으면 실행한다. 알려진 설정 없는 실패나 설정 검색을 재사용 증명으로 반복하지 않는다. 필요한 재현·기준 비교·독립 검증은 유지하고 그 목적을 task에 기록한다. 환경 설정이 정상인 코드 테스트 실패는 환경 절차 무효화와 구분한다.

검토 단계는 공유 diff와 task 근거를 대조하여 실제 지식 변화인지 판정한다. 동일 재사용 기록만 추가했다면 불필요한 변경으로 지적하고 기존 복귀 절차로 코드 변경 단계에서 정정한다. verify의 추출·공유 문서 수정 금지는 유지한다. 작성 단계의 불변 판단이 먼저이고, 검토 지적은 누락을 발견하는 보완 경로다.

다음 가설은 채택하지 않았다.

- 기존 “재사용만으로 다시 쓰지 않는다” 한 문장이 충분하다: 후속 두 Work가 모두 재검증을 새 공유 기록으로 승인받은 실제 증거로 기각했다. 변경 전 비교와 verify 검토 기준을 명시했다.
- 실제 환경 실패를 해결하면 항상 새 지식이다: 이미 알려진 지원 절차와 동일 범위로 해결한 실패는 실행 이력이다. 발견과 실행을 구분한다.
- 모든 help/doctor 또는 설정 없는 명령을 금지하면 개선된다: 현재 적용 확인·재현·기준 비교에 필요한 실행까지 잃으므로 채택하지 않았다.
- 테스트 수·Work UUID를 제거하면 모든 중복을 안전하게 자동 판별할 수 있다: 같은 명령도 범위·유효성·근거가 바뀔 수 있다. 문자열 필터·자동 삭제·유사도 서비스·고정 저장 용량을 만들지 않았다.
- 모든 재사용 때 기존 문서를 정리하면 된다: 그 자체가 관리 작업을 만든다. 불변을 기본으로 하며 실제 중복 통합이 필요할 때만 고유 사실·원발견·변경 근거와 출처를 보존한다. 개발 결과 문서를 소급 정리하지 않았다.
