## 목표
반품 전표(`src/invoice/credit-note.js`)의 환불 금액이 회계팀 계산과 몇 원씩 어긋나는 문제를 바로잡는다. 예: CN-0112(청구서 INV-2047의 반품)의 환불 합계 19,182원이 회계팀 계산과 다르다.

## 비목표
- 이미 발행된 청구서와 이미 만든 반품 전표는 다시 계산하지 않는다(저장된 금액 그대로 사용).
- `src/format/` 서식 모듈의 출력 형식은 바꾸지 않는다.
- 청구서(`total.js`)와 견적(`quote.js`)의 계산은 이번 요청 범위가 아니다.

## 원하는 결과
- 새로 만드는 반품 전표의 부가세와 환불 합계가 회계팀 규정(아래 제약)대로 계산된다.
- `examples/CN-0112.json`을 `examples/INV-2047.json`에 적용해 만든 전표의 환불 합계가 회계팀 계산과 일치한다.

## 완료조건
- [ ] 재현 절차(CN-0112 / INV-2047)가 더 이상 실패하지 않는다: 환불 합계가 회계팀 규정대로 계산한 값과 같다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] 이미 저장된 `totals`가 있는 반품 전표와 청구서는 `creditNoteTotals` 등에서 재계산 없이 저장된 값을 그대로 돌려준다
- [ ] `src/format/`의 출력 형식 테스트 결과가 달라지지 않는다
- [ ] 영세율 반품 전표는 부가세 0, 면세 줄은 부가세에 포함되지 않는다는 점이 테스트로 확인된다

## 제약
- (팀 지식 docs/knowledge/billing/vat-per-line-floor.md) 부가세는 과세 줄마다 할인 적용 후 줄 금액(net)에 `VAT_RATE_PERCENT`%를 곱해 원 단위 버림하고 그 합을 쓴다. 합계에서 다시 반올림하지 않는다(회계팀 규정). 반품 전표도 공용 함수 `src/money.js`의 `vatOfLines`를 쓴다. 영세율 문서는 부가세 0, 면세 줄은 제외.
- (팀 지식 docs/knowledge/billing/issued-invoice-stored-totals.md) 발행된 청구서는 저장된 `totals`를 그대로 쓰고 다시 계산하지 않는다.
