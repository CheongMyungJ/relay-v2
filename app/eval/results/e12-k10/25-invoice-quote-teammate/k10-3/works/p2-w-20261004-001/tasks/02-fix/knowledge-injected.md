# 부가세는 과세 줄마다 할인 후 금액의 10%를 원 단위 버림으로 계산해 합산한다

## 규칙
- 부가세 = 과세 품목 줄마다 `floor(할인 후 줄 금액 × 10%)`를 구해 더한 값이다 (회계팀 규칙).
- 합계(과세 공급가액 합)에서 다시 반올림하지 않는다. 예: INV-2031은 줄별 536+633+325+837+310 = 2,641원, 합계 29,079원 (합계 반올림이면 2,644원).
- 면세 줄은 부가세 0, 영세율 청구서는 부가세 0이다.

## 아직 정하지 않은 것
- 견적서(`src/invoice/quote.js`)와 반품 전표(`src/invoice/credit-note.js`의 `creditTotals`)에 같은 줄별 버림 규칙을 적용할지: 사람이 정한다. 지금 코드는 합계 `Math.round` 방식(Work w-20261004-001)

# 부가세는 과세 줄마다 할인 후 금액 × 10%를 원 단위 버림해 더한다 (회계팀 규칙)

## 규칙
- 부가세는 과세 품목 줄마다 (할인 적용 후 줄 금액 × 10%)를 원 단위 버림으로 계산하고, 그 합이 부가세다. 합계에서 다시 반올림하지 않는다. 예: INV-2031 부가세 536+633+325+837+310 = 2,641원, 합계 29,079원.
- 청구서(`computeTotals`), 견적서(`quoteTotals`), 반품 전표(`creditTotals`)가 모두 `src/invoice/total.js`의 `lineVat`을 같이 쓴다. 면세 줄과 영세율 문서의 부가세는 0이다.
- 저장된 `totals`가 있는 문서(발행된 청구서, 만들어 둔 반품 전표)는 다시 계산하지 않고 저장된 값을 그대로 쓴다.
- 반품 전표 예: CN-0112(청구서 INV-2047의 반품) 줄별 부가세 923+612+207 = 1,742원, 환불 합계 19,180원(회계팀 값).

## 아직 규칙을 따르지 않는 곳
- `src/invoice/total.js`의 `computeTotals`: 과세 공급가액 합계에 10%를 곱해 `Math.round`한다. 이 브랜치에서 줄별 버림으로 고치지 않았다(Work w-20261004-002는 반품 전표만 고침. 앞 Work w-20261004-001이 고쳤을 수 있음, 머지 대기).
- `src/invoice/quote.js`의 `quoteTotals`: 할인 전 금액 합과 할인 합에 각각 `percentOf`를 적용해 뺀다. 줄별 버림이 아니다(위와 같은 사정).

## 아직 정하지 않은 것
- 반품 전표 부가세와 원 청구서 부가세의 맞물림(보정 여부): 사람이 판단한다. 지금 코드는 보정 없이 반품 전표를 새 규칙으로만 계산한다(Work w-20261004-001, w-20261004-002). 옛 규칙으로 저장된 청구서와는 INV-2047 전부 반품 3원(5,801 대 5,798), CN-0112 일부 반품 2원(1,744 대 1,742) 차이가 난다.
