# fix: 요약 메일 중복 발송 수정 (키에서 runId 제거, 느린 성공 유지, 서버 간 선점)

## 요약
아침 요약 메일이 같은 날 2~3통 나가던 문제를 고쳤다. 재시도는 그대로 두고, 같은 고객·같은 날짜 요약은 경로와 관계없이 한 번만 나가게 했다.

## 원인
- `src/digest/key.js`가 중복 방지 키에 `runId`를 넣어, 재실행·수동 실행·재시작 때마다 키가 달라 ledger가 중복을 못 막았다.
- `src/digest/deadline.js`가 발송이 성공한 뒤에도 걸린 시간이 제한(3000ms)을 넘으면 시간 초과로 던졌다. 이미 나간 메일을 재시도해 최대 maxAttempts(3)통이 나갔다("가끔 3통").
- `has` 확인과 `markSent` 사이에 await가 있어 동시 실행이 둘 다 통과했다.

## 변경
- key.js: 키를 `digest:기간:사용자`로. 실행별 건수는 ledger entry의 runId로 센다.
- deadline.js: 느린 성공은 결과를 버리지 않고 `slow`만 알린다(진짜 시간 초과 오류는 그대로 재시도).
- ledger.js/runner.js: 보내기 전 `claim`으로 확인과 선점을 한 번에 하고 실패하면 해제한다. 옛 키 형식도 `hasLegacy`로 함께 본다(배포일 호환). `dedupe/store.js`에 읽기 전용 `keys()` 추가.
- 재시도 설정과 코드는 변경하지 않았다.
- docs/knowledge/digest/ 에 규칙 3건 추가.
