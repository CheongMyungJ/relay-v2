# fix: 성공한 발송이 재시도되거나 요약이 재실행에서 다시 나가던 중복 발송 수정

## 요약
같은 알림이 두 번, 가끔 세 번 가던 문제를 고쳤다. 메일에서 더 잦았다. 재시도 기능과 횟수는 그대로이고, 실제로 실패한 발송만 다시 보낸다.

## 원인
- `decide()`가 성공 여부보다 걸린 시간을 먼저 봐서, 제한 시간을 넘긴 성공도 `timeout`으로 재시도했다.
- 요약의 `withDeadline()`이 성공한 발송도 제한 시간을 넘기면 예외를 던져 다시 보냈다.
- 요약 중복 방지 키에 `runId`가 들어 있어, 같은 기간을 다시 실행하면 "이미 보냄" 검사가 소용없었다.
- 메일은 SMTP 중계로 지연이 길어 제한 시간을 넘기기 쉬워 더 자주 났다.

## 변경
- `src/retry/policy.js`: `outcome.ok`를 먼저 판정. 실패이면서 시간을 넘긴 경우는 지금처럼 재시도.
- `src/digest/deadline.js`: 성공한 발송은 느려도 예외를 던지지 않음.
- `src/digest/key.js`, `src/digest/runner.js`: 요약 키를 사용자+기간으로 변경. 실행별 집계는 기록의 `runId`로 가능.

## 테스트
- `npm test`: 80개 통과. 기준 커밋의 src에서는 새 테스트 4개 실패.
- 추가: 느린 성공은 한 번만 발송(즉시·요약), 같은 기간 재실행은 재발송 없음, 실제 시간 초과 실패는 재시도(즉시·요약). 기존 테스트 변경 없음.
- 알려진 한계: 응답만 유실된 경우의 중복은 멱등 키가 필요해 이번 범위 밖. 키 형식 변경 직후 이미 보낸 기간을 재실행하면 한 번 더 나갈 수 있음.
