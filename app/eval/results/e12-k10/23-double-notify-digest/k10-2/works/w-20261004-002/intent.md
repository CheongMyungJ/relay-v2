## 목표
아침 요약 메일(전날 알림 모음)이 같은 날 두 통, 가끔 세 통 가는 문제를 없앤다. 고객은 요약 메일을 하루에 한 번만 받아야 한다.

## 비목표
- 실제로 실패한 요약 발송의 재시도를 끄거나 줄이지 않는다.
- 요약 메일 외 일반 알림 발송 경로의 동작 변경은 이번 요청 범위가 아니다. 단, 같은 원인이 그 경로에도 있으면 handoff에 알린다.

## 원하는 결과
- 요약 메일이 한 번 성공적으로 발송되면, 이후 어떤 경로(재시도, 스케줄러 재실행 등)로도 같은 날 같은 고객에게 다시 발송되지 않는다.
- 실제로 못 보낸 요약은 지금처럼 다시 발송되어, 하루를 건너뛰지 않는다.
- 요약 발송이 거치는 각 경로마다 고객이 한 번만 받는다는 근거(테스트 또는 실행 결과)가 있다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] 요약 발송 성공 후 재시도·재실행이 일어나는 각 경로에서 같은 날 같은 고객에게 발송이 한 번만 일어남을 보이는 테스트가 있다
- [ ] 실제로 실패한 요약 발송은 여전히 다시 발송됨을 보이는 테스트가 있다
- [ ] 제한 시간을 넘겼지만 성공한 요약 발송은 다시 발송되지 않음을 보이는 테스트가 있다
- [ ] 경로별로 "고객이 한 번만 받는다"는 근거가 목록으로 정리되어 있다

## 제약
- (팀 지식 `docs/knowledge/dispatch/retry-only-failed-sends.md`) 재시도 기능 자체를 끄거나 줄이면 안 된다. 실제로 실패한 발송(transient 오류, 시간 초과로 실패한 발송)은 지금처럼 다시 보낸다.
- (팀 지식 `docs/knowledge/dispatch/retry-only-failed-sends.md`) 발송이 성공했으면 제한 시간(`send.timeoutMs`, `digest.sendTimeoutMs`)을 넘겼어도 다시 보내지 않는다. 시간 초과는 실패한 발송에만 적용한다.

## 추가 의견
- 요청에 원인 추정은 없다. 원인 분석은 fix 단계에서 한다.
