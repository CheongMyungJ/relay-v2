# 요약 메일 중복 발송 수정: 성공한 느린 발송 재시도 중단, 요약 키에서 runId 제거

## 요약
아침 요약 메일이 같은 날 두 통 이상 가던 문제를 고쳤다. 실제로 실패한 발송의 재시도는 그대로 유지한다.

## 원인
- `withDeadline()`이 성공한 발송도 제한 시간을 넘기면 시간 초과 오류를 던져, 이미 간 요약을 실패로 보고 재시도했다.
- `digestKey()`에 `runId`가 있어 스케줄러 재시작·수동 재실행 때 중복 방지가 작동하지 않았다.

## 변경
- `src/digest/deadline.js`: 성공이면 던지지 않고 `slow`만 표시. 시간 초과는 실패한 발송에만 적용.
- `src/digest/key.js`: 키를 `digest:${period}:${userId}`로 변경(`runId`는 원장 항목에 유지).
- `src/digest/sent-store.js`(신규), `ledger.js`, `runner.js`, `notifier.js`: 발송 직전 공유 저장소에서 키를 원자적으로 예약하고 실패하면 해제해, 서버 두 대가 동시에 돌아도 한 통만 보낸다. `createNotifier({ digestSentStore })`로 운영 저장소를 주입(기본은 메모리). 느린 성공은 `digest.slow` 지표와 경고 로그.
- `docs/knowledge/`: 재시도 규칙 갱신, 요약 키 규칙 추가.
