# fix: 요약 메일 중복 발송 수정 (느린 성공 재시도, 키의 runId, 동시 실행)

## 요약
아침 요약 메일이 같은 날 두 통, 가끔 세 통 나가던 문제를 고쳤다. 같은 기간의 요약은 수신자당 한 통만 나가고, 실패한 요약은 이후 실행에서 다시 보낸다.

## 원인
- `withDeadline`이 발송이 성공한 뒤에도 제한 시간을 넘기면 시간 초과를 던져, 이미 나간 메일을 재시도했다(최대 3통).
- 요약 키에 runId가 들어 있어 다른 runId로 같은 기간을 다시 돌리면 중복 방지가 듣지 않았다.
- 확인과 기록 사이가 원자적이지 않아 동시 실행이 둘 다 보낼 수 있었다.

## 변경
- `src/digest/deadline.js`: 성공이면 던지지 않고 `slow: true`로 알린다. `runner.js`가 `digest.send.slow` 지표를 올린다.
- `src/digest/key.js`: 키를 `digest:기간:사용자`로. 실행별 집계는 원장 항목의 runId로 한다.
- `src/digest/ledger.js`, `runner.js`: 보내기 전 `claim`, 실패 시 `release`.
- `docs/knowledge/delivery/`: 지식 항목 2개 정리.
- 실패한 발송은 기록되지 않아 이후 실행에서 다시 보내진다(건너뛰지 않음).

## 알려진 한계
- 서버 두 대가 원장을 따로 쓰면(`src/notifier.js:70`, 인스턴스별 메모리 원장) 이 수정으로 막히지 않는다. 원장을 공유하면 1분·30분 간격과 동시 실행 모두 한 통임을 테스트로 확인했다. 원장을 따로 쓰는 경우는 `todo` 테스트로 남겼다.

## 테스트
- `npm test`: 82 통과, 0 실패, todo 1(원장 비공유 서버 두 대, 현재 2통).
- 추가: 서버 두 대(원장 공유: 1분, 30분, 동시), 느린 성공, 다른 runId 재실행, 동시 실행, 실패 후 재발송, 느린 실패 재시도. 기준 코드에서는 재현 테스트가 실패한다.
