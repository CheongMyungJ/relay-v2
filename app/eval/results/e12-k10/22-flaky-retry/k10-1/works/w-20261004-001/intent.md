## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 간헐 실패의 진짜 원인을 찾아 코드에서 고친다.

## 비목표
- 시험에 재시도를 붙이거나, skip 하거나, 시간 제한을 늘리는 식의 우회는 하지 않는다.
- 이번 실패와 무관한 기능 변경이나 리팩터링은 하지 않는다.
- 병렬 실행(동시 4개)을 순차 실행으로 되돌리거나 동시 실행 수를 줄이는 식으로 고치지 않는다. 순차로 하면 밤 배치가 제시간에 끝나지 않는다.

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 report가 항상 자기 job에 대응한다. `ci/batch.test.js`가 반복 실행해도 안정적으로 통과한다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm test`와 `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `ci/batch.test.js`를 여러 번(예: 20회) 연속 실행해도 모두 통과한다
- [ ] `ci/batch.test.js`의 재시도, skip, 시간 제한 증가 없이 통과한다
- [ ] 수정 후에도 밤 배치는 동시 4개 병렬 실행을 유지한다 (동시 실행 수 설정과 실제 동시 실행이 4로 유지됨)
- [ ] 반복 실행(횟수와 통과/실패 결과)을 근거로 handoff에 기록한다

## 제약
- 로컬 `npm test`는 늘 통과하고 CI 전용 시험(지연 사용)에서만 간헐적으로 실패한다.

## 추가 의견
- 실패 로그: `expected report-6 to belong to job-6, got job-5` (재실행하면 통과)
