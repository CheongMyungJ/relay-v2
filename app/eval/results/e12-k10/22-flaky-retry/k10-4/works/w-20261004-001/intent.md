## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 문제를 고친다. 조회 지연이 있을 때 밤 배치 결과(보고서)가 엉뚱한 작업에 붙는 것이 드러난 증상이므로, 시험이 아니라 제품 동작이 지연 순서와 무관하게 올바르도록 만든다.

## 비목표
- 시험에 재시도를 붙이거나 skip하거나 시간 제한을 늘리는 것 (요청에서 해결이 아니라고 명시)
- `ci/batch.test.js`의 검증을 약화하거나 지연 설정(`LATENCY`)을 줄여 실패를 가리는 것
- 배치 병렬 실행(동시 4개)을 순차 실행으로 되돌리거나 동시 실행 수를 줄이는 것 (병렬 유지는 사람 요구)
- 밤 배치와 관계없는 기능 변경이나 리팩터링

## 원하는 결과
조회 지연과 지터가 있어도 `runBatch` 결과의 모든 보고서가 자기 작업(jobId)과 고객사 데이터에 맞게 붙는다. `ci/batch.test.js`가 반복 실행해도 늘 통과한다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다 (`ci/batch.test.js`를 여러 번 반복 실행해도 실패하지 않는다)
- [ ] `npm run test:ci`가 통과한다 (`npm test`도 통과한다)
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `ci/batch.test.js`를 연속 20회 반복 실행한 결과(실행 횟수와 통과 횟수)를 verify 보고에 남기고, 20회 모두 통과한다
- [ ] 시험 쪽 재시도, skip, 시간 제한 증가 없이 통과한다
- [ ] 실패를 일으키는 조건(작업 완료 순서가 바뀌는 지연)을 결정적으로 재현하는 회귀 시험이 `npm test`에 추가된다

## 제약
- 배치 병렬 실행(동시 4개)은 유지한다 (사람)
- 시험에 재시도, skip, 시간 제한 늘리기를 쓰지 않는다 (사람)

## 추가 의견
- 요청에 사람이 의심한 원인 위치는 없다.
