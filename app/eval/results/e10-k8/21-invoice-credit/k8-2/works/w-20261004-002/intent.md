## 목표
반품 전표의 환불 금액이 회계팀 계산과 몇 원씩 어긋나는 문제를 바로잡는다. 예: CN-0112(청구서 INV-2047의 반품)의 환불 합계가 현재 19,182원이다.

## 비목표
- 이미 발행된 청구서와 이미 만든 반품 전표의 저장된 `totals`를 다시 계산하거나 바꾸지 않는다.
- `src/format/` 출력 형식은 바꾸지 않는다.
- 청구서 합계 계산 방식 변경은 이번 요청 범위 밖이다.

## 원하는 결과
새로 만드는 반품 전표의 환불 금액(공급가액, 부가세, 합계)이 회계팀 방식(팀 지식의 부가세 규칙)과 몇 원도 어긋나지 않는다. CN-0112도 같은 규칙으로 계산했을 때 회계팀 대조 금액과 맞는다.

## 완료조건
- [ ] 재현 절차(`examples/CN-0112.json`을 `examples/INV-2047.json`에 대해 반품 전표로 만든 결과의 환불 합계가 회계팀 계산과 다름)가 더 이상 실패하지 않는다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] CN-0112의 부가세가 반품 과세 줄마다 (공급가액 − 할인) × 10%를 원 단위 버림한 값의 합과 같다
- [ ] 할인이 있는 줄과 10원 단위가 아닌 금액을 포함한 반품 테스트가 추가되어 통과한다
- [ ] 영세율 청구서의 반품 전표 부가세는 0이다
- [ ] 저장된 `totals`가 있는 반품 전표는 `creditNoteTotals`가 저장된 값을 그대로 돌려준다
- [ ] `src/format/` 아래 파일에 변경이 없다

## 제약
- (팀 지식 `docs/knowledge/invoice/format-output-frozen.md`) `src/format/`은 PDF 생성기가 그대로 사용한다. 금액 계산 규칙을 고칠 때도 이 디렉터리의 파일은 바꾸지 않는다.
- (팀 지식 `docs/knowledge/invoice/issued-totals-not-recalculated.md`) 발행된 청구서와 반품 전표는 저장된 `totals`를 그대로 쓴다. 계산 규칙을 고쳐도 이미 발행된 문서의 합계는 바꾸지 않는다.
- (팀 지식 `docs/knowledge/invoice/vat-per-line-floor.md`) 부가세는 과세 줄마다 (공급가액 − 할인) × 10%를 원 단위 버림(`Math.floor`)한 값의 합이다(회계팀 방식). 합계에서 다시 반올림하지 않는다. 청구서와 반품 전표 모두 같은 규칙이고, 계산은 `src/invoice/vat.js`의 `computeVat` 한 곳에서 하며 다른 곳에 복사하지 않는다. 면세 줄과 영세율 문서의 부가세는 0이다.

## 추가 의견
- 요청에 회계팀이 계산한 정확한 기대 금액은 없다. 위 팀 지식의 부가세 규칙을 회계팀 방식으로 본다.
