# fix: 같은 기간 요약 메일이 중복 발송되지 않게 수정

## 요약
아침 요약 메일이 같은 날 두세 통 가던 문제를 고친다. 같은 기간 요약은 고객이 한 번만 받는다. 재시도 횟수와 기능은 그대로다.

## 원인
1. 발송이 성공해도 3초를 넘기면 시간 초과 오류로 던져 이미 간 요약을 재시도했다(최대 3회).
2. 요약 키에 runId가 있어 재실행·재시작마다 키가 달라져 보낸 기록 검사가 무력했다.
3. 검사(has)와 기록(markSent) 사이에 await가 있어 겹쳐 도는 실행이 둘 다 보냈다.

## 변경
- `deadline.js`: 느린 성공은 `slow` 표시만 하고 지표 `digest.slow`와 경고 로그를 남긴다.
- `key.js`: 키를 기간+사용자로만 정한다.
- `ledger.js`/`runner.js`: 보내기 전 `claim`, 실패하면 `release`(메시지 생성 실패 포함).
- 팀 지식 `docs/knowledge/digest/digest-key-and-claim.md` 추가, `retry/slow-success-is-not-failure.md` 갱신.

## 테스트
- `npm test`: 82개 통과. 기준 커밋에서는 새 테스트 5건 실패.
- 경로별 테스트(재시도, 수동 재실행, 스케줄러 재실행, 동시 실행)와 실제 실패 재시도 테스트 추가. 기존 테스트는 변경 없음.
- 한계: 프로세스 재시작은 새 스케줄러+같은 ledger로 대신 검증.

## 알려진 한계 (후속 필요)
- **서버 두 대가 동시에 같은 사용자 요약을 보내는 경우는 이 PR로 막히지 않는다.** 레포의 ledger는 메모리 구현뿐이라 `claim`이 프로세스 안에서만 유효하다(`src/digest/ledger.js`). 배포 당일 다른 서버에서 한 번 더 도는 경우도 같다.
- 후속: 공유 DB ledger. 조건부 삽입(unique 키 등)으로 `claim`을 원자적으로 하고, 선점 만료(lease TTL)를 두어 선점한 채 죽은 서버의 요약이 건너뛰어지지 않게 한다. 키는 이미 기간+사용자로 서버 간에 안정적이다.
