# 느리게 성공한 발송을 시간 초과로 보고 다시 보내던 중복 발송 수정

## 요약
일부 고객이 같은 알림을 두 번, 가끔 세 번 받던 문제를 고친다. 메일은 응답이 느려 더 자주 겪었다.

## 원인
발송이 성공했어도 걸린 시간이 제한 시간(메일 2초, 요약 3초)을 넘으면 시간 초과 실패로 보고 다시 보냈다.
- `src/retry/policy.js` `decide`: 시간 초과 검사가 성공 검사보다 앞에 있었다.
- `src/digest/deadline.js` `withDeadline`: 성공한 호출도 시간이 넘으면 예외를 던져, 보낸 기록 없이 재시도되었다.

## 변경
- 성공이면 시간과 무관하게 완료로 처리한다. 시간 초과 판단은 실패일 때만 쓴다.
- `withDeadline`은 예외 대신 `slow` 표시를 돌려주고, 느린 성공은 `send.<채널>.slow`, `digest.slow` 지표로 남긴다.
- 재시도 기능과 정책 값은 바꾸지 않았다. 실제 실패(어댑터 시간 초과 오류)는 그대로 재시도된다.
- 재시도 규칙을 `docs/knowledge/retry/`에 남겼다.

## 테스트
- `npm test`: 81건 통과.
- `test/duplicate-send.test.js` 7건 추가. 느린 성공 4건(메일·푸시·요약·decide)은 수정 전 실패, 수정 후 통과하고, 실제 시간 초과 재시도 3건(메일·푸시·요약)은 전후 모두 통과한다.
- 알려진 위험: 요약 키에 runId가 있어 같은 기간을 재실행하면 요약이 또 나갈 수 있다(이번 범위 밖).
