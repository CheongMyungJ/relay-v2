# 요약 메일 중복 발송 수정: 느린 성공을 실패로 보지 않고, 발송 키에서 실행 ID를 뺀다

## 요약
아침 요약 메일이 같은 날 2~3통 나가던 문제를 고쳤다. 재시도 기능과 정책은 그대로 두었다.

## 원인
1. `withDeadline`이 정상 반환한 발송도 3000ms를 넘으면 `SendTimeoutError`로 바꿔, 이미 도착한 요약을 재시도로 다시 보냈다.
2. `digestKey`에 `runId`가 들어 있어 재기동·재실행·동시 실행마다 새 키가 되어 중복 방지가 듣지 않았다.

## 변경
- `deadline.js`: 느린 성공은 성공으로 두고 `slow`만 알림. runner는 `digest.slow` 지표와 경고 로그만 남김.
- `key.js`: 키를 `digest:<period>:<userId>`로.
- `ledger.js`/`runner.js`: 보내기 전 `claim`, 실패하면 `release`(준비 단계 오류 포함)로 동시 실행도 막음.
- `docs/knowledge/`: 요약 키 규칙 추가, 재시도 규칙에 요약 적용 추가.

## 테스트
- `npm test`: 80건 통과(기준 74건).
- 경로별: [중복 방지/느린 성공], [재실행], [동시 실행] 각 1통. 실제 실패는 [재시도 유지/시간 초과 실패], [실패 뒤 재실행], [준비 단계 오류]에서 재발송됨.
- 기존 테스트는 바꾸지 않았다.
