# 요약 메일 중복 발송 수정: 늦은 성공을 성공으로 보고 요약 키에서 runId 제거

## 요약
아침 요약 메일이 같은 날 두 통, 가끔 세 통 전달되던 문제를 원인 두 가지를 고쳐 해결한다. 성공한 요약은 한 번만, 실제로 실패한 요약은 다시 보내져 결국 한 번 전달된다.

## 원인
- `withDeadline`이 발송 성공 뒤 걸린 시간이 제한을 넘으면 시간 초과 오류를 던져, 이미 나간 메일을 실패로 보고 재시도했다(최대 3통).
- 중복 방지 키 `digestKey`에 runId가 있어, 같은 기간을 다른 runId로 다시 돌리면 보낸 기록을 못 찾고 다시 보냈다.

## 변경
- `src/digest/deadline.js`: 값을 돌려줬으면 걸린 시간과 무관하게 성공. 소요 시간은 `digest.send.ms` 지표로 남는다.
- `src/digest/key.js`, `src/digest/runner.js`: 키를 `digest:{period}:{userId}`로 변경. 보내는 중인 키도 다시 보내지 않는다(겹친 실행 방지).
- 재시도 횟수·간격 정책은 그대로.
- `docs/knowledge/delivery/`에 지식 항목 정리.

## 테스트
- `npm test`: 79 통과. 새 테스트 5개(최초 발송, 재시도, 다른 runId 재실행, 실패 후 재발송, 겹친 실행)는 수정 전 코드에서 모두 실패.
- 남은 위험: ledger가 메모리 TTL이라 재시작 뒤 재실행은 운영의 공유 DB 전제. `digest.sendTimeoutMs`는 효과 없음.
