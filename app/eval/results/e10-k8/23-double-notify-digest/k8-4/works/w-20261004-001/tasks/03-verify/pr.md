# fix: 느리게 성공한 발송을 시간 초과로 보고 다시 보내던 중복 발송 수정

## 요약
성공했지만 제한 시간보다 느린 발송을 실패로 보고 재시도해 같은 알림이 2~3번 나가던 문제를 고쳤다. 발송 경로와 요약 경로 모두 해당한다.

## 원인
`src/retry/policy.js`의 `decide`가 `outcome.ok`보다 `elapsedMs > timeoutMs`를 먼저 검사해 느린 성공을 timeout 실패로 처리했다. 요약 경로의 `withDeadline`도 성공 뒤 같은 방식으로 오류를 던졌다. 응답이 느린 메일에서 더 자주 나타났고, 재시도 3회 때문에 세 번 나가기도 했다.

## 변경
- `src/retry/policy.js`: 성공이면 시간과 관계없이 `done`. 실패한 발송은 그대로 재시도.
- `src/digest/deadline.js`: 성공한 발송을 시간 초과 오류로 바꾸지 않음.
- 재시도를 끄거나 횟수를 줄이지 않았다.
- `docs/knowledge/retry/`에 규칙과 알려진 위험을 남겼다.

## 테스트
- `npm test`: 79 pass, 0 fail.
- 수정 전 코드에서는 새 테스트 3개가 실패하는 것을 확인했다.
- 실제 실패한 메일은 재시도로 다시 발송됨을 검증하는 테스트를 추가했다.
