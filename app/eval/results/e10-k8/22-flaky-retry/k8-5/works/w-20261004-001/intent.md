## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 간헐 버그의 원인을 찾아 코드에서 고친다. 밤 배치에서 보고서가 엉뚱한 작업의 결과로 붙는 일이 없어야 한다.

## 비목표
- 시험에 재시도를 붙이거나, skip하거나, 시간 제한을 늘리는 것은 해결이 아니므로 하지 않는다.
- 순차 실행으로 되돌리는 것도 해결이 아니다. 병렬 실행(동시 4개)은 유지한다.
- 조회 지연 값(`LATENCY`)이나 시험의 기대값을 바꿔 증상만 가리지 않는다.
- 밤 배치와 관계없는 기능 변경이나 리팩터링은 하지 않는다.

## 원하는 결과
지연과 완료 순서가 어떻게 달라져도 각 보고서(`report-N`)는 자기 작업(`job-N`)의 기록에만 붙고, `npm run test:ci`가 반복해서 돌려도 매번 통과한다.

## 완료조건
- [ ] 재현 절차(`npm run test:ci`를 반복 실행해 `ci/batch.test.js`가 간헐적으로 실패하는 현상)가 더 이상 실패하지 않는다
- [ ] `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `ci/batch.test.js`를 여러 번(예: 30회) 연속 실행해도 한 번도 실패하지 않는다
- [ ] 반복 실행의 횟수와 통과/실패 결과를 검증 보고서에 남긴다
- [ ] 병렬 실행(동시 4개)이 유지된다
- [ ] 수정은 시험이 아니라 `src/`의 원인 코드에 있고, 재시도·skip·시간 제한 증가가 없다

## 제약
- 로컬 `npm test`는 계속 통과해야 한다.

## 추가 의견
- 로컬 `npm test`는 늘 통과하고 CI 전용 시험(지연 있음)에서만 가끔 실패한다. 재실행하면 통과한다.
