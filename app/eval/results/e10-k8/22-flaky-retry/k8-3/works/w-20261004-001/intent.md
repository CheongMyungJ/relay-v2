## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 원인을 찾아, 시험이 아닌 제품 코드의 결함을 고친다.

## 비목표
- `ci/batch.test.js`에 재시도 추가, skip, 시간 제한 늘리기 등 시험 쪽 우회
- 병렬 실행(동시 4개)을 순차 실행으로 되돌리거나 동시성 수를 줄이는 것
- 이번 실패와 무관한 리팩터링이나 기능 변경

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 보고서(report-N)가 항상 자기 작업(job-N)에 속한다. 실행 순서나 지연 타이밍에 따라 결과가 달라지지 않는다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `npm test`가 통과한다
- [ ] `ci/batch.test.js`를 반복 실행(예: 20회 연속)해도 모두 통과하고, 그 반복 실행 결과(횟수와 통과 수)를 근거로 보고한다
- [ ] 병렬 실행(동시 4개)이 그대로 유지된다
- [ ] `ci/batch.test.js`에 재시도, skip, 시간 제한 증가가 추가되지 않는다

## 제약
- 병렬 실행(동시 4개)은 유지한다. 순차 실행으로 되돌리는 것은 해결이 아니다.
- 로컬 `npm test`는 늘 통과하므로, 지연이 있는 타이밍에서만 드러나는 문제로 본다.
