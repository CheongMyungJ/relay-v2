## 목표
CI 전용 시험 `ci/batch.test.js`(밤 배치를 실제와 비슷한 지연으로 실행)가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 문제의 근본 원인을 찾아 고친다.

## 비목표
- 시험에 재시도를 붙이거나 skip하는 것
- 시험의 시간 제한(timeout)을 늘리는 것
- 시험의 지연 값이나 검증 조건을 완화하는 것
- 배치를 순차 실행으로 되돌리는 것 (병렬 실행은 유지)
- 이번 버그와 무관한 리팩터링이나 기능 변경

## 원하는 결과
밤 배치를 어떤 조회 지연과 순서로 돌려도 보고서 결과가 항상 제 작업(job)에 붙는다. 즉 `report-N`의 결과는 늘 `job-N`의 기록으로 나온다. 재실행해야 통과하는 일이 없어진다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다 (`ci/batch.test.js`를 반복 실행해도 `expected report-N to belong to job-N` 실패가 나오지 않는다)
- [ ] `npm run test:ci`가 통과한다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `ci/batch.test.js`를 여러 번(예: 20회 이상) 연속 실행해 모두 통과한다
- [ ] 배치의 병렬 실행(동시 4개)이 유지된다 (순차 실행으로 바꾸거나 동시 실행 수를 줄이지 않는다)
- [ ] 수정이 시험이 아닌 `src/` 코드의 원인을 고친 것이다 (재시도, skip, 시간 제한 증가 없음)

## 제약
- 재시도, skip, 시간 제한 증가는 해결로 인정하지 않는다 (요청 원문).
- 배치의 병렬 실행(동시 4개)은 유지한다. 순차 실행으로 되돌리는 것은 해결이 아니다 (사람).

## 추가 의견
- 실패는 가끔만 나고 재실행하면 통과한다. 로컬 `npm test`에서는 늘 통과한다.
