## 목표
CI의 `npm run test:ci`에서 ci/batch.test.js가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 원인을 찾아 코드에서 고친다.

## 비목표
- 시험에 재시도를 붙이거나 skip하는 것
- 시간 제한(timeout)을 늘리는 것
- 시험의 검증을 약화하는 것
- 배치를 순차 실행으로 되돌리는 것 (병렬 실행, 동시 4개는 유지한다)

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 report가 항상 자기 job에 속한다(report-N은 job-N). 실행 시점이나 지연 순서에 따라 결과가 달라지지 않는다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm run test:ci`가 통과한다 (로컬 `npm test`도 통과한다)
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `npm run test:ci`를 여러 번(예: 20회) 반복 실행해도 ci/batch.test.js가 매번 통과한다
- [ ] 배치가 동시 4개 병렬 실행을 유지한다
- [ ] 반복 실행(`npm run test:ci` 20회)의 통과 횟수를 검증 결과에 근거로 기록한다
- [ ] 수정이 시험 쪽 재시도, skip, 시간 제한 변경 없이 제품 코드(또는 시험의 잘못된 가정)의 원인을 해결한다

## 제약
- 재시도, skip, 시간 제한 증가는 해결로 인정하지 않는다 (요청 원문)
- 병렬 실행(동시 4개)을 유지한다 (사람)

## 추가 의견
- 로컬 `npm test`는 ci/ 시험을 포함하지 않아 늘 통과한다. 재현은 `npm run test:ci`로 한다.
