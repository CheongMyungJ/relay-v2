## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 실패하는 문제(`expected report-6 to belong to job-6, got job-5`)의 원인을 찾아 코드에서 고친다. 재실행하면 통과하므로 지연 시간(타이밍)에 따라 간헐적으로 드러나는 문제다.

## 비목표
- 시험에 재시도를 붙이거나, skip하거나, 시간 제한을 늘리는 것은 해결이 아니므로 하지 않는다.
- 병렬 실행(동시 4개)을 순차 실행으로 되돌리거나 동시성을 낮추는 것은 해결이 아니므로 하지 않는다.
- 시험의 기대값을 바꿔 실패를 가리지 않는다.
- 이번 버그와 무관한 리팩터링이나 기능 추가는 하지 않는다.

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 report가 항상 자기 job에 속한다(report-N은 job-N). 실행 순서나 지연이 달라도 결과가 바뀌지 않는다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `npm test`가 계속 통과한다
- [ ] `ci/batch.test.js`를 여러 번 반복 실행해도(예: 20회) 한 번도 실패하지 않는다
- [ ] 병렬 실행(동시 4개)이 그대로 유지된다
- [ ] 반복 실행 횟수와 통과/실패 결과가 검증 결과(handoff)에 기록된다
- [ ] 수정이 `ci/batch.test.js`의 재시도, skip, 시간 제한 변경 없이 소스 코드(`src/`)에서 이루어진다

## 제약
- 시험을 느슨하게 만드는 방식(재시도, skip, 시간 제한 증가)은 해결로 인정하지 않는다.
- 병렬 실행(동시 4개)은 유지한다. 순차 실행으로 되돌리는 것은 안 된다.

## 추가 의견
- 로컬 `npm test`는 항상 통과하고, 지연이 있는 CI 전용 시험에서만 가끔 실패한다.
