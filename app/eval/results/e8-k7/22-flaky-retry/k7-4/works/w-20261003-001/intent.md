## 목표
CI의 `npm run test:ci`에서 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패한다. 이 간헐 실패의 원인을 찾아 코드에서 고친다.

## 비목표
- 시험에 재시도를 붙이거나, skip하거나, 시간 제한을 늘리는 방식의 해결은 하지 않는다.
- 병렬 실행(동시 4개)을 유지한다. 순차 실행으로 되돌려 해결하지 않는다.
- `ci/batch.test.js`의 검증 내용을 약화하지 않는다.
- 이번 실패와 무관한 기능 추가나 리팩터링은 하지 않는다.

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 report가 항상 자기 job에 속한다(report-N은 job-N). 실행 타이밍과 무관하게 결과가 일정하다.

## 완료조건
- [ ] 재현 절차(실제와 비슷한 지연으로 `ci/batch.test.js`를 반복 실행)가 더 이상 실패하지 않는다
- [ ] `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `npm test`도 계속 통과한다
- [ ] 동시 4개 병렬 실행 설정이 그대로 유지된다
- [ ] 고쳤다는 근거로 `ci/batch.test.js`를 여러 번 반복 실행(예: 연속 20회)한 결과가 모두 통과한다
- [ ] 수정은 시험 파일이 아니라 원인이 있는 소스 코드에서 이루어진다
- [ ] 같은 실패가 타이밍에 의존하지 않고 재현·검증되도록, 원인을 드러내는 시험이 추가되거나 기존 시험이 그 경우를 덮는다

## 제약
- 로컬 `npm test`는 늘 통과하고 CI 전용 시험(`ci/`)에서만 실패한다.

## 추가 의견
- 재실행하면 통과하므로 간헐 실패(타이밍 의존)이다.
