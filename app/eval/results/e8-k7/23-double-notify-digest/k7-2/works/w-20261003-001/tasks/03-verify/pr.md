# fix: 느리게 성공한 발송을 실패로 보고 다시 보내던 중복 발송 수정

## 요약
같은 알림이 고객에게 2~3번 가던 문제를 고쳤다. 발송은 성공했는데 제한 시간을 넘겼다는 이유로 실패 처리해 재시도하던 것이 원인이다. 재시도 정책은 바꾸지 않았고 실제 실패는 그대로 다시 보낸다.

## 원인
- `src/retry/policy.js`의 `decide()`가 성공 여부보다 먼저 시간 초과를 검사해, 도착한 발송도 재시도했다(최대 3통).
- 요약 메일은 `withDeadline()`이 성공 뒤에 시간 초과 오류를 던졌고, 요약 키에 `runId`가 들어 있어 재실행 때 이미 보낸 요약을 걸러내지 못했다.

## 변경
- `policy.js`: 성공이면 걸린 시간과 관계없이 `done`
- `deadline.js`: 성공을 오류로 바꾸지 않고 `slow` 플래그만 반환, `runner.js`에서 `digest.slow` 지표 증가
- `key.js`: 요약 키에서 `runId` 제거 (배포 전 옛 키 기록은 한 번 중복될 수 있음)
- 지식: `docs/knowledge/`에 규칙·실패 유형·이력 3건 추가

- 기존 테스트 변경 없음
