# 요약 메일 중복 발송 수정: 느린 성공·재실행·서버 두 대 동시 실행에서 한 통만

## 요약
아침 요약 메일이 같은 날 두 통, 가끔 세 통 가던 문제를 고쳤다. 재시도는 그대로이고 실제로 못 보낸 요약은 다시 보낸다.

## 원인
- 발송이 성공했는데 제한 시간(3초)보다 느리면 `withDeadline`이 시간 초과 오류를 던져 성공한 요약을 재시도했다.
- 이미 보냈는지 키에 runId가 들어 있어 재실행(새 runId)에서는 중복 확인이 무효였다.
- 확인(`has`)과 기록(`markSent`)이 따로라 서버 두 대가 동시에 돌면 둘 다 통과했다.

## 변경
- `src/digest/deadline.js`: 성공을 오류로 바꾸지 않고 `slow`만 표시. runner는 `digest.slow` 지표와 경고 로그로 남김.
- `src/digest/key.js`: 키에서 runId 제거.
- `src/digest/ledger.js`, `runner.js`: 보내기 전에 `claim`으로 키 선점, 실패하면 `release`로 풀어 재시도·재실행이 보낼 수 있게 함.
- `src/notifier.js`: 공용 ledger를 주입하는 `digestLedger` 옵션.
- `docs/knowledge/digest-runs-on-two-servers.md`: 서버 두 대 동시 실행 규칙 기록.
- `maxAttempts` 등 재시도 설정은 변경 없음.

## 테스트
- `npm test`: 83건 통과(기준 74건). 새 테스트 9건: 느린 성공, 재실행, 느린 성공 뒤 재실행, 실패 후 재시도로 한 번 전달, 실패 뒤 재실행, 서버 두 대 동시 실행, 한쪽이 보낸 뒤 다른 서버 시작, 선점 후 실패 시 해제, 포기 후 재실행.
- 기준 커밋 소스에서는 새 테스트 7건 실패 확인.
- 서버 두 대는 공용 ledger를 흉내 낸 시험이다. 운영 DB가 원자적 선점을 지원하는지는 확인 필요.
