# fix: 요약 메일 중복 발송 수정 (느린 성공 오판, 실행마다 달랐던 요약 키)

## 요약
아침 요약 메일이 같은 날 두세 통 나가던 문제를 고쳤다. 증상을 가리는 수정(건너뛰기, 재시도 끄기)은 하지 않았다.

## 원인
1. `withDeadline`이 제한 시간(3000ms)을 넘겨 성공한 발송을 `SendTimeoutError`로 던져, 이미 전달된 요약을 기록 없이 재시도(최대 3통).
2. 요약 키에 `runId`가 있어 재실행·재시작·수동 실행은 이전 발송을 알아보지 못함.

## 변경
- `src/digest/deadline.js`, `runner.js`: 느린 성공은 성공 처리하고 `digest.send.slow` 지표와 경고 로그만 남김. 실제 오류는 기존대로 재시도.
- `src/digest/key.js`: 키를 `digest:<기간>:<사용자>`로. 실행별 집계는 기록의 `runId`로 유지.
- `src/digest/scheduler.js`: 발송을 포기한 사용자가 있으면 다음 tick이 같은 기간을 다시 돈다.
- `docs/knowledge/digest-key-period-user-only.md`: 키 규칙 기록.

경로별로 고객이 한 번만 받는 근거:
| 경로 | 근거 |
|---|---|
| 정기 실행(tick) | 하루 한 번(`lastPeriod`)이고 기록 키로 한 번 더 막힘. 이틀 연속 시험 |
| 느린 성공 | 성공이면 즉시 기록하고 재시도 없음. 시험 2개 |
| 오류 재시도 | 일시 오류만 재시도, 성공 시 기록해 이후 안 보냄. 시험 |
| 재실행·수동·재시작 | 키가 기간+사용자라 `already`로 건너뜀. 시험 3개 |
| 포기한 요약 | 기록되지 않아 다음 tick/실행에서 다시 보내지고 한 통만 전달. 시험 2개 |

## 테스트
- `npm test` → 83 통과, 0 실패 (수정 전 코드에서는 7개 실패).
- 기존 시험은 바꾸지 않고 9개 추가.
- 남은 위험: 동시 실행 잠금 없음, 영구 오류 사용자는 같은 날 매 tick 재시도.
