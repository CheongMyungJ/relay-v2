# fix: 아침 요약 메일이 같은 날 2~3통 가던 중복 수정

## 요약
느리게 성공한 요약을 시간 초과로 보고 재발송하던 것, 실행마다 달라지던 보낸 키, 동시 실행 중복을 고쳤다. 재시도 기능과 정책은 그대로이고 실패한 요약은 이전처럼 다시 보낸다.

## 원인
- `withDeadline`이 성공한 호출도 걸린 시간이 제한을 넘으면 시간 초과 오류로 던져 이미 도착한 요약이 재시도로 2~3번 더 갔다.
- 보낸 키에 `runId`가 있어 재시작·수동·다중 서버 재실행 때 이전 발송에 걸리지 않았다.
- 키 확인과 기록 사이에 원자성이 없어 같은 기간 실행이 겹치면 둘 다 보냈다.

## 변경
- `src/digest/deadline.js`, `runner.js`: 성공은 시간을 넘겨도 성공(`slow` 표시와 경고 로그).
- `src/digest/key.js`: 키에서 `runId` 제거(`digest:<period>:<userId>`).
- `src/digest/ledger.js`, `runner.js`: 발송 전 `claim`으로 선점, 성공은 `markSent`, 실패는 `release`(10분 뒤 만료)로 재시도 유지.
- `docs/knowledge/`: 팀 지식 3건 추가.

## 테스트
- `npm test` 80건 통과. `test/digest.test.js`에 6건 추가(느린 성공 1회, 시간 초과 오류 재시도, runId 달라도 재발송 없음, 건너뛰기 없음, 동시 실행 1통, 동시 실행 중 실패 시 재시도). 기존 테스트 변경 없음.
- 남은 위험: 어댑터 시간 초과 오류 뒤 재시도 중복(멱등 키 없음), ledger가 서버 간 공유되려면 공유 저장소의 원자적 선점 필요.
