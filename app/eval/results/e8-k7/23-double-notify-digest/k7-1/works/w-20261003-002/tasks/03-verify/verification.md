## 리뷰 지적
1. [사소] test/digest.test.js(느린 성공 테스트) — 경고 로그(`요약 발송이 제한 시간보다 오래 걸렸지만 성공`)를 검증하지 않는다. 로그 검증을 추가하자.
2. [사소] test/digest.test.js(시간 초과 오류 재시도 테스트) — 재시도를 maxAttempts까지 소진해 `failed`로 끝나는 경우는 새 테스트가 보지 않는다(기존 재시도 테스트가 일부 덮음).
3. [권장] src/digest/runner.js:40-52 — 보낸 키 확인(`ledger.has`)과 기록(`markSent`) 사이에 await이 있어 같은 기간의 실행이 겹치면 둘 다 확인을 통과해 2통 간다. 사람이 "요약 일정 작업이 서버 두 대에서 같이 돌고 배포일엔 한 번 더 돈다"고 알려 줬으므로 실제 문의 경로다. 직접 돌려 보니 같은 ledger에서 동시 실행 2통, ledger가 따로인 서버 2대 2통. 제안: 발송 전에 키를 원자적으로 선점하고 실패하면 풀어 준다.
(참고: 어댑터가 던진 시간 초과 오류 뒤 재시도는 서버가 이미 받았으면 중복될 수 있으나 멱등 키가 없다. 실패 건 재시도 유지는 비목표라 지적이 아니라 `남은 위험`에 적는다.)

## 남은 위험
- 어댑터가 시간 초과 오류를 던진 뒤 재시도는 서버가 이미 받았다면 중복될 수 있다(멱등 키 없음, 요약 헤더 X-Notify-Digest는 중복 제거에 쓰이지 않음). 실패 건 재시도 유지가 비목표라 그대로 둠.
- ledger는 메모리 구현이라 서버끼리 공유되지 않는다. 서버 두 대에서 한 통만 가려면 운영 저장소가 공유되고 `claim`이 SET NX 같은 원자적 선점이어야 한다(이 레포에서는 서버 간 동작을 검증하지 못함).
- 선점 만료(10분)보다 오래 걸리는 발송이나, 보낸 키 TTL(`ledgerTtlMs` 3일) 뒤 같은 기간 재실행은 다시 보낼 수 있다.
- src/retry/policy.js decide()의 같은 시간 초과 판정 문제는 앞 Work(w-20261003-001)에서 고쳤을 수 있음, 머지 대기.
