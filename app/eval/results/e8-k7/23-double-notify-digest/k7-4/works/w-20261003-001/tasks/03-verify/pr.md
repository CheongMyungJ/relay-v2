# fix: 느리게 성공한 발송을 시간 초과로 보고 다시 보내던 중복 수정

## 요약
일부 고객이 같은 알림(특히 메일)을 두 번, 가끔 세 번 받던 문제를 고쳤다. 재시도 기능과 횟수는 그대로다.

## 원인
발송이 성공했어도 걸린 시간이 제한 시간(일반 2000ms, 요약 3000ms)을 넘으면 실패(timeout)로 보고 다시 보냈다. `decide()`가 성공 여부보다 경과 시간을 먼저 검사했고, `withDeadline()`은 성공 뒤에 예외를 던졌다.

## 변경
- `src/retry/policy.js`: 성공이면 경과 시간과 무관하게 `done`.
- `src/digest/deadline.js`: 성공한 발송은 느려도 값을 돌려줌. 주석 정리.
- 실패한 발송의 재시도는 그대로.

## 테스트
- `npm test`: 80개 통과.
- 추가: 느리게 성공한 메일·푸시·요약은 한 번만 발송, 실패(timeout 오류 포함)는 재시도. 수정 전 코드에서는 3개 실패.
