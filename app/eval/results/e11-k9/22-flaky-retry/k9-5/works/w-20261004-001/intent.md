## 목표
CI 전용 시험 `ci/batch.test.js`가 가끔 `expected report-6 to belong to job-6, got job-5`로 실패하는 원인을 찾아 제품 코드(또는 실제 결함이 있는 곳)에서 고친다.

## 비목표
- 시험에 재시도를 붙이거나, skip하거나, 시간 제한을 늘려서 통과시키는 것
- 병렬 실행(동시 4개)을 순차 실행으로 되돌리는 것
- 이번 실패와 관계없는 기능 변경이나 리팩터링

## 원하는 결과
밤 배치를 실제와 비슷한 지연으로 돌려도 각 report가 항상 자기 job에 속한다. `npm run test:ci`가 재실행 없이 안정적으로 통과한다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다
- [ ] `npm test`와 `npm run test:ci`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] `ci/batch.test.js`를 여러 번 반복 실행(예: 20회 연속)해도 실패하지 않는다
- [ ] 배치가 여전히 동시 4개로 병렬 실행된다(순차 실행으로 되돌리지 않는다)
- [ ] 수정이 시험의 재시도, skip, 시간 제한 증가에 의존하지 않는다

## 제약
- 시험을 느슨하게 만드는 방식(재시도, skip, 시간 제한 늘리기)은 해결로 인정하지 않는다.
- 병렬 실행(동시 4개)은 유지해야 한다. 순차 실행으로 되돌리는 것은 해결이 아니다.

## 추가 의견
- 로컬 `npm test`는 늘 통과하고 CI 전용 시험만 가끔 실패한다. 재실행하면 통과한다.
