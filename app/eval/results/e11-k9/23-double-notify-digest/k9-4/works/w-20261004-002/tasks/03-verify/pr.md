# fix: 요약 메일 중복 발송 수정 (느린 성공 재시도, 발송 키 runId, 실패분 재실행)

## 요약
아침 요약 메일이 같은 날 두세 통씩 나가던 문제를 고쳤다. 실제로 못 보낸 요약은 다시 나간다.

## 원인
- `withDeadline`이 이미 성공한 발송을 제한 시간(3000ms) 초과로 바꿔 던져, 같은 요약을 재시도로 또 보냈다(최대 3통).
- `digestKey`에 `runId`가 있어 실행마다 키가 달라졌고, 재시작·재실행 때 "이미 보냄" 확인이 통하지 않았다.
- 스케줄러는 최종 실패한 요약을 다시 돌리지 않아 하루를 건너뛸 수 있었다.

## 변경
- `src/digest/deadline.js`: 느린 성공은 `slow: true`만 표시한다.
- `src/digest/key.js`: 키를 `digest:${period}:${userId}`로 한다(실행별 건수는 ledger의 `runId`로 센다).
- `src/digest/runner.js`: 새 키 사용, 느린 성공은 `digest.slow` 지표와 경고 로그만 남긴다.
- `src/digest/scheduler.js`: 실패가 남으면 다음 tick에서 같은 기간을 다시 돌린다(기간당 3번까지, 받은 사람은 건너뜀).
- 팀 지식 2건 추가(`docs/knowledge/delivery/`).
