# fix: 제한 시간을 넘겨 성공한 발송을 다시 보내던 중복 발송 수정

## 요약
느리게 성공한 발송을 시간 초과로 보고 재시도해 같은 알림이 두 번 이상 가던 문제를 고쳤다. 실제로 실패한 발송의 재시도는 그대로다.

## 원인
`decide()`가 `outcome.ok`보다 `elapsedMs > timeoutMs`를 먼저 검사했고, 요약 경로의 `withDeadline`은 성공 뒤에도 시간 초과 오류를 던졌다. 이미 나간 메일/푸시를 다시 보내 중복이 생겼다. 응답이 느린 메일 채널에서 더 자주 났다.

## 변경
- `src/retry/policy.js`: 성공을 시간 초과 검사보다 먼저 처리
- `src/digest/deadline.js`: 성공한 발송은 시간이 넘어도 값을 돌려주고 `elapsedMs`만 알려 줌
- 테스트 3개 추가 (느린 성공 2개, 실패 후 재시도 1개)

## 테스트
- `npm test`: 77개 통과
- 수정 전 코드에서는 느린 성공 테스트 2개가 실패함을 확인
- 알려진 한계: ETIMEDOUT처럼 오류로 끝났지만 실제로는 보내졌을 수 있는 경우는 멱등 키 없이는 막지 못함. `withDeadline`의 `timeoutMs`는 미사용
