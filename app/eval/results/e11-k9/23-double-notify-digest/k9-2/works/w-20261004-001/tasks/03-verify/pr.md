# fix: 제한 시간을 넘겨 성공한 발송을 재시도하지 않도록 수정

## 요약
성공한 발송이 제한 시간을 넘겼다는 이유로 실패 처리되어 같은 알림이 두 번, 가끔 세 번 나가던 문제를 고쳤다. 실제로 실패한 발송은 지금처럼 재시도한다.

## 원인
`decide`(즉시 발송)가 `outcome.ok`보다 먼저 경과 시간을 검사했고, `withDeadline`(요약 발송)은 성공 후에도 시간이 넘으면 `SendTimeoutError`를 던졌다. 둘 다 이미 나간 알림을 timeout 실패로 보고 재시도해 중복이 났다. SMTP가 더 느려지기 쉬워 메일에서 더 잘 드러났다.

## 변경
- `src/retry/policy.js`: 성공이면 시간과 무관하게 `done`.
- `src/digest/deadline.js`: 성공한 발송을 시간 초과로 던지지 않음.
- `test/duplicate-send.test.js`: 재현 테스트 4개 추가 (메일·푸시·요약 한 번만 발송, 실제 실패는 재시도).
- `docs/knowledge/retry/`: 재시도 유지 규칙과 이번 유형의 함정 기록.

## 테스트
- `npm test`: 78개 통과 (기존 74 + 신규 4)
- 수정 전 코드에서는 신규 테스트 3개 실패 확인
- 한계: 소켓 timeout 오류인데 서버는 이미 발송한 경우는 여전히 재시도되어 중복될 수 있음 (별도 설계 필요)
