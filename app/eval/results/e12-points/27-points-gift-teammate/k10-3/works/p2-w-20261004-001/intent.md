## 목표
선물하기 주문 G-0213의 적립 예정 포인트가 고객센터 계산 기준과 같은 218P로 나오게 `src/gift/gift-points.js`를 고친다. 지금은 249P로 나와 같은 상품을 일반 주문으로 샀을 때와 다르다는 문의가 들어왔다.

## 비목표
- 선물 메시지 카드, 받는 사람 정보, 영수증 글자(`src/format/`)는 바꾸지 않는다.
- 이미 적립된 포인트(`points.earned`)는 다시 계산하지 않는다.
- 일반 주문의 적립 계산(`src/points/earn.js`)은 바꾸지 않는다.

## 원하는 결과
- G-0213(`examples/G-0213.json`)의 적립 예정 포인트가 218P다. 고객센터 계산 기준이며 사람이 알려 준 값이다.
- 선물하기 적립이 같은 상품을 일반 주문으로 샀을 때의 적립과 같은 값을 낸다.

## 완료조건
- [ ] 재현 절차(G-0213의 적립 예정 포인트 계산)가 더 이상 실패하지 않는다. 결과가 249P가 아니라 218P다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] G-0213의 적립 예정 포인트가 218P임을 확인하는 테스트가 있다
- [ ] 같은 상품·쿠폰·사용 포인트로 만든 일반 주문과 선물하기 주문의 적립 포인트가 같다
- [ ] `src/format/` 아래 파일, 선물 메시지 카드와 받는 사람 검증 코드는 바뀌지 않는다
- [ ] 이미 저장된 `points.earned` 값을 다시 계산하는 코드가 추가되지 않는다

## 제약
- (팀 지식 `docs/knowledge/points/earn-basis.md`) 일반 주문의 적립 기준은 배송비를 뺀 결제 금액(`amounts.total − amounts.shipping`)의 `POINT_RATE_PERCENT`%이고 1P 미만은 버린다. 이미 적립된 값은 재계산하지 않고 주문에 저장된 값을 쓴다.
- 위 지식은 선물하기에도 같은 기준을 적용할지를 "사람이 따로 정한다"로 남겨 두었다. 이번에는 사람이 고객센터 기준 218P를 목표로 줬다. 일반 주문 로직과 이 값이 맞는지는 fix에서 코드로 확인한다.

## 추가 의견
- 사람은 일반 주문의 규칙을 정확히 모른다. 동료가 고객센터와 맞췄다고만 들었고, 그 동료는 휴가 중이다.
