## 목표
부분 환불 때 회수하는 포인트(`pointsRecovered`)가 정산팀 계산과 1~2P씩 어긋나는 문제를 고친다. 회수 포인트를 정산팀 기준으로 맞춘다.

## 비목표
- 이미 적립된 포인트(`points.earned`)와 이미 처리한 환불은 다시 계산하지 않는다.
- 환불 금액(`refundAmount`)과 영수증 글자(`src/format/`)는 바꾸지 않는다.
- 전체 취소(`cancelOrder`)의 회수 방식은 바꾸지 않는다.
- 주문 적립(`src/points/earn.js`)과 선물하기 적립(`src/gift/`)은 이번 범위가 아니다.

## 원하는 결과
부분 환불의 회수 포인트 = 주문에 저장된 원래 적립 포인트 − 남은 상품으로 다시 계산한 적립 포인트.
- 남은 상품 적립 = (남은 상품 금액 − 쿠폰 할인 − 사용 포인트)의 `POINT_RATE_PERCENT`%, 1P 미만 버림(반올림 아님). 배송비는 제외.
- 쿠폰 할인과 사용 포인트는 남은 주문에 그대로 둔다(안분하지 않는다).
- 예: O-1077 / R-0311은 남은 상품 34,180 − 5,000 − 2,000 = 27,180 → 271P, 회수 = 403 − 271 = 132P.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다 (O-1077 / R-0311의 `pointsRecovered`가 132)
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] 이전에 부분 환불한 수량(`alreadyRefunded`)이 있어도 남은 상품 기준으로 회수가 계산되고, 여러 번 부분 환불한 회수 합이 저장된 적립 포인트를 넘지 않는다
- [ ] 환불 금액과 `src/format/` 출력은 수정 전과 같다
- [ ] 회수 계산 테스트가 추가된다(R-0311 132P 포함)

## 제약
- (팀 지식 docs/knowledge/points/earn-basis.md) 적립 기준은 (상품 금액 − 쿠폰 할인 − 사용 포인트)의 적립률% 버림, 배송비 제외. 단 같은 문서의 "부분 환불 회수 = 환불 상품 금액의 적립률% 버림"은 이번 요청의 사람 답과 어긋난다(사람 답을 따름).
- 저장된 `points.earned`는 다시 계산하지 않고 그대로 쓴다.
