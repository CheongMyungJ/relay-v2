## 목표
기본 적립률을 1%에서 2%로 올려 새 주문의 적립 포인트가 새 적립률로 계산되게 한다.

## 비목표
- 이미 저장된 `points.earned`와 ledger는 다시 계산하지 않는다(저장된 값 그대로).
- 영수증 글자(`src/format/`)는 바꾸지 않는다.
- 부분 환불 때 회수 포인트(`src/orders/refund.js`)를 새 비율로 계산할지는 이번 범위가 아니다. 정산팀과 따로 정하며, 이번에는 환불 회수 계산을 바꾸지 않는다.

## 원하는 결과
- 예시 주문 O-1107(`examples/O-1107.json`)이 486P 적립된다. (상품 27,350 − 쿠폰 2,000 − 사용 포인트 1,020 = 24,330원 × 2% = 486.6 → 버림 486P, 배송비 제외)
- 일반 주문과 선물하기 적립이 같은 새 적립률(2%)과 같은 계산 기준을 쓴다.

## 완료조건
- [ ] 재현 절차가 더 이상 실패하지 않는다: O-1107로 주문을 만들면 `points.earned`가 486이다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] 적립률 값(`POINT_RATE_PERCENT`)이 2다
- [ ] 선물하기 적립도 2%로 계산된다
- [ ] 부분 환불 회수 계산 결과는 이번 변경 전과 같다(기존 환불 테스트 통과)
- [ ] `src/format/`의 영수증 출력 결과가 바뀌지 않는다(기존 영수증 테스트 통과)
- [ ] 이미 저장된 `points.earned`와 ledger 값을 다시 계산하는 코드가 없다

## 제약
- (팀 지식 `docs/knowledge/points/earn-basis.md`) 적립 = (상품 금액 − 쿠폰 − 사용 포인트) × `POINT_RATE_PERCENT`%, 배송비 제외, 소수점 버림. 일반 주문과 선물하기는 `earnPoints`(`src/points/earn.js`) 한 곳을 쓴다.
- 이미 저장된 `points.earned`와 ledger는 다시 계산하지 않는다. 전체 취소는 저장된 값을 쓴다.
