## 목표
일반 주문의 적립 예정 포인트가 고객센터 계산보다 많게 나오는 버그를 고친다. 주문 O-1042는 268P가 아니라 237P여야 한다.

## 비목표
- 선물하기 적립(`src/gift/gift-points.js`)은 수정하지 않는다.
- 영수증 글자(`src/format/`)는 바꾸지 않는다.
- 이미 적립된 포인트(주문에 저장된 `points.earned`)는 다시 계산하지 않는다.

## 원하는 결과
- `examples/O-1042.json`으로 주문을 만들면 적립 예정 포인트가 237P다.
- 다른 일반 주문도 고객센터 계산과 같은 값으로 적립된다.
- 저장된 주문의 적립 값, 영수증 출력, 선물하기 적립은 지금과 같다.

## 완료조건
- [ ] 재현 절차(O-1042 적립 예정 포인트 237P)가 더 이상 실패하지 않는다
- [ ] `npm test`가 통과한다
- [ ] 기존 테스트를 약화하거나 삭제하지 않는다
- [ ] O-1042의 적립 예정 포인트가 237P임을 확인하는 테스트가 있고 통과한다
- [ ] 이미 저장된 주문의 `points.earned`를 읽는 경로(영수증, 환불)는 저장된 값을 그대로 쓴다
- [ ] `src/format/`과 `src/gift/gift-points.js`는 변경되지 않는다

## 제약
- 포인트는 1P = 1원, 적립률은 `src/config.js`의 `POINT_RATE_PERCENT`를 따른다.

## 추가 의견
- 요청에서 확인 대상으로 지목한 파일은 `src/points/earn.js`다. (사람 추정, 확인 안 됨)
- "다른 주문도 조금씩 많게 나온다"는 요청 설명이며, 어떤 주문이 얼마나 다른지는 확인되지 않았다.
