  - 경험 전체 relay (relay 8, pre 6) — B는 앱이 채운 후보와 에이전트의 선택지 질문 덕에 수고가 적고 흐름이 분명했다. A는 통제력은 좋았지만 사람이 잘못된 분류를 직접 짚어야 했다.
- 판정 #2: 결과 선호 relay — A와 B 모두 바뀐 파일이 없다. 그래서 실제로 정리한 결과는 비교할 수 없고, 시험을 더하지도 않았다. 다만 기록상 숨긴 시험은 A가 다섯 항목 모두 통과했고, B는 '낡은 항목'에서 실패했다. 그래서 A를 조금 더 높게 봤다. 변경이 없는데 시험이 통과했다는 점은 기록 자체가 어색하다. 그래서 A의 correctness도 3점에 그쳤다.
  - 경험 전체 relay (relay 8, pre 6) — A는 후보 자동 채움으로 입력 없이 끝났고 애매한 건을 먼저 물어 줬다. B는 요청을 직접 쓰고 누락된 legacy-prefix를 사람이 지적해야 했으며 discount-name은 그대로 남았다. B가 변경 이력을 남긴 점은 장점이다.
- 판정 #3: 결과 선호 relay — 두 결과 모두 바뀐 파일이 없고 diff도 비어 있다. 이 기록만 보면 정리가 실제로 이뤄졌다고 보기 어렵다. 다만 숨긴 시험에서 A는 중복 합침과 낡은 항목에서 실패했고, B는 다섯 항목을 모두 통과했다. 기록 안에서는 B가 요구를 더 많이 충족했다. 그런데 B는 변경이 없는데도 합침 시험을 통과해서, 기록이 서로 맞지 않는다. 그래서 B의 correctness는 3으로 제한했다. 둘 다 시험을 추가하지 않았다.
  - 경험 전체 relay (relay 7, pre 6) — B가 입력 부담이 없고 후보로 시작해 정리 범위가 분명했으며, 낡은 anchor까지 고쳤다. A는 통제력은 좋았으나 일부를 미해결로 남겼다. B는 단계가 많고 경고가 헷갈렸다.

### 사람 역할의 말

- [relay#1 좋음] 지식 정리 후보를 새 Work 창에서 바로 채워 줬다. 에이전트가 애매한 환불 규칙과 옛 접두 코드를 지우기 전에 선택지로 물어봤다. 완료조건별 판정표와 diff도 확인하기 쉬웠다.
- [relay#1 불편] 요청 글상자에 '코드는 건드리지 마'를 직접 덧붙일 기회가 없었다. 앱이 채운 요청을 그대로 시작했다. 리뷰 단계 터미널에 handoff 누락 경고가 길게 나와 읽기 번거로웠다.
- [relay#2 좋음] 지식 정리 후보를 앱이 미리 찾아서 요청에 채워 줬다. 애매한 두 건(legacy-prefix 삭제, 환불 규칙)은 에이전트가 선택지로 물어봤고, 나머지는 판정표와 diff로 확인할 수 있었다.
- [relay#2 불편] 리뷰 단계 터미널에 handoff.md에 줄이 없다는 경고 메시지가 길게 남아 있어서, 문제가 있는 건지 헷갈렸다. 의도 초안이 분량 기준을 넘었다는 경고도 있었다.
- [relay#3 좋음] 새 Work 창의 지식 정리 후보 목록과 [지식 정리 Work로 채우기]로 요청이 바로 채워졌다. 애매한 두 건(환불 규칙, 옛 쿠폰 코드)은 에이전트가 지우기 전에 선택지로 물어봤다. 판정표에는 완료조건마다 근거가 붙어 있었다.
- [relay#3 불편] 승인 단계가 여러 번 이어졌고, 터미널 선택지와 오른쪽 패널을 오가야 했다. 터미널에는 handoff에 고친 지식 줄이 없다는 경고 목록이 길게 떠서 문제인지 헷갈렸다. 의도 초안이 분량 기준을 넘었다는 경고도 있었다.
- [pre#1 좋음] 의도 정리 단계에서 완료조건과 확인 방법이 표로 나오고, 내가 지적한 legacy-prefix와 환불 가정이 바로 반영됐다. 마지막 판정표와 전체 diff로 결과를 검증하기 쉬웠다.
- [pre#1 불편] 의도 초안이 분량 기준을 넘는다는 경고가 떴는데 그대로 넘어갔다. 에이전트가 legacy-prefix를 처음엔 건드리지 않는 항목으로 둬서 내가 짚어야 했다.
- [pre#2 좋음] 충돌하는 환불 규칙을 에이전트가 먼저 선택지로 물어 줬다. 완료조건별 판정표와 근거가 있어서 결과를 믿기 쉬웠다.
- [pre#2 불편] 낡은 legacy-prefix 문서를 에이전트가 먼저 묻지 않아서 내가 직접 짚어야 했다. 코드에 없는 anchor인 discount-name도 낡았을 수 있는데 그대로 둔 채 넘어갔다.
- [pre#3 좋음] 에이전트가 애매한 항목(환불 충돌, 코드에 없는 anchor, 중복)을 선택지로 물어봤다. 의도 요약과 완료조건별 판정표, 전체 diff 덕분에 결과를 확인하고 승인하기 쉬웠다.
- [pre#3 불편] 일반 유형이라 유형 선택과 단계 흐름이 처음엔 낯설었다. 리뷰 단계에서 형식 검사 오류를 고치는 로그가 터미널에 길게 나와 읽기 번거로웠다.
