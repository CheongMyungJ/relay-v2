- 판정 #1: 결과 선호 relay — 두 결과 모두 숨긴 시험과 레포 시험을 통과했고, 7곳을 모두 한 모듈로 모았으며 공개 함수의 위치와 시그니처도 유지했다.

A는 시험을 하나도 추가하지 않았다. 회귀를 막는 장치가 없어 tests는 1점이다. 코드에도 군더더기가 있다.
- `lateFeeAsOf`는 쓰는 곳이 없다.
- JSDoc에 `uncappedWithoutDeposit` 설명이 `@param`에 섞여 들어가 있다.
- `overdue.js`에 `deposit === null`일 때 fee를 null로 만드는 우회 처리가 호출부에 있다. 규칙이 한 곳에 모였다고 보기 어렵다.
- `invoice.js`의 null 판정은 `amount===0 && days<=grace`라서 돌아가긴 하지만 읽기 불편하다.

B는 안전망 테스트(`late-fee-safety.test.js`)를 더했다. 이 테스트는 모으기 전 동작을 고정한다. 파트너 내림, 보증금 없는 옛 계약, 안내 문자의 유예 없음 같은 차이를 코드 주석과 옵션으로 드러냈다. `depositCap` 옵션으로 기존 동작을 보존했고 `isChargeable`도 분리했다. 다만 `depositCap`의 `'compare'` 모드는 다소 복잡하다. B의 테스트는 출력이 일부 잘려서 전부 확인하지는 못했지만, 의도에 맞는 구성으로 보인다.

따라서 B가 낫다.
  - 경험 전체 relay (relay 7, 맨 CLI 6) — A는 빠르고 수고가 적었지만 deposit 동작이 조용히 바뀌어 사람이 직접 짚어야 했다. B는 시간과 차례가 더 들었어도 차이를 먼저 묻고 승인 단계를 거쳤으며, 안전망 테스트와 판정표로 믿을 근거도 더 주었다.

- 판정 #3: 결과 선호 relay — B가 더 낫다. 두 결과 모두 일곱 곳을 모았고 세 가지 의도된 차이(파트너 내림, 옛 계약 보증금 없음, 문자 유예 없음)를 지켰다. 함수 시그니처도 그대로다.

B는 숨긴 시험을 모두 통과했다. 규칙이 lateFee.js 한 곳에 있고, 호출처는 옵션만 넘긴다. 안전망 시험 두 파일도 더했다. 다만 invoice.js에서 withinGrace를 따로 쓰는 점은 조금 아쉽다.
  - 경험 전체 cli (relay 6, 맨 CLI 7) — A는 짧고 효율적이었고 핵심 차이 두 가지를 먼저 물었다. 다만 보증금 없는 옛 계약은 언급이 없고 요약이 길었다. B는 반올림과 보증금 null을 묻고 테스트로 근거를 주었지만, reminder 유예는 사람이 직접 짚어야 했고 절차와 경고로 수고가 컸다.

### 사람 역할의 말

- [relay#1 좋음] 에이전트가 동작이 다른 곳(문자 무유예, 정산 내림, 보증금 없는 경우)을 먼저 짚어 물어봐서 내가 의도를 답할 수 있었다. 판정표에 완료조건마다 근거가 붙어 있어 확인하기 쉬웠다.

- [relay#2 좋음] 에이전트가 복사본끼리 결과가 다른 곳(내림, 유예 없음, 보증금 null)을 먼저 짚어 물었고, 판정표에 완료조건별 근거가 있어 믿고 승인할 수 있었다.
- [relay#2 불편] GitHub 게시 실패 경고가 내내 떠 있었고, 작업과 무관한 건지 알기 어려워 신경이 쓰였다.
- [relay#3 좋음] 에이전트가 의도 정리에서 반올림 차이, 보증금 null 같은 애매한 지점을 먼저 짚어 물어봤다. 단계마다 완료조건과 판정표가 있어서 확인하기 쉬웠다.
- [relay#3 불편] gh 로그인이 없어서 이슈 게시 실패 경고가 계속 떴다. 작업과는 상관없지만 거슬렸다. 또 에이전트가 reminder 유예 차이는 묻지 않아서 내가 직접 짚어 줘야 했다.
- [cli#1 좋음] 에이전트가 코드 간 동작 차이(내림/반올림, 유예, deposit 비어 있음)를 스스로 찾아 보고했다. 예전 코드와 직접 비교한 표와 결과도 보여 줘서 믿을 만했다.
- [cli#1 불편] 첫 결과에서는 deposit이 빈 경우의 동작이 조용히 바뀌어 있었고, 내가 짚고 나서야 알게 됐다. 최종 구조에 옵션과 임시 처리 코드가 남아 첫 요청보다 덜 깔끔하다.
- [cli#2 좋음] 복사본끼리 달랐던 부분(유예 없음, 내림, 보증금 null)을 에이전트가 스스로 찾아 옵션으로 남기고 보고해 줘서, 동작 차이를 놓치지 않고 확인할 수 있었다.
- [cli#2 불편] 보증금 null 처리는 처음엔 모든 호출처에 퍼져 동작이 바뀐 채로 보고됐다. 에이전트가 먼저 알려 줘서 다행이었지만, 내가 물어야 알 수 있었다면 놓쳤을 수 있다. 루트 경로 rm 권한 경고가 뜬 것도 잠깐 당황스러웠다.
- [cli#3 좋음] 복사본끼리 규칙이 다른 곳(문자의 무유예, 파트너 정산의 내림)을 에이전트가 스스로 찾아냈다. 이를 합치지 않고 물어봐서 내가 의도를 설명할 수 있었다.
- [cli#3 불편] 요약이 길어서 어디로 모았는지만 짧게 보고 싶다는 내 선호와는 맞지 않았다. 질문이 요약 중간에 섞여 있어서 한 번 더 읽어야 했다.
