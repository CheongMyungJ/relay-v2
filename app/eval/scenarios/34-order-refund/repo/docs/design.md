# shopline 설계

주문 서버의 설계. 결정은 아래 표에 번호를 붙여 적고, 바꾸면 변경 이력에 남긴다.

## 1. 결정

| # | 결정 | 이유 | 사람 결정 |
|---|---|---|---|
| D1 | 주문은 장바구니 확정 때 만든다. 상태는 `pending_payment` → `paid` → `shipped` → `delivered` | 결제 전 주문도 남겨 고객센터가 본다 | 사람 |
| D2 | 결제는 주문을 확정할 때 결제사 API를 동기로 호출하고 응답을 받은 뒤 주문을 `paid`로 바꾼다 | 결제 결과를 바로 보여 준다 | 사람 |
| D3 | 금액은 원 단위 정수로 다룬다 | 소수 오차를 막는다 | 사람 |
| D4 | 역할은 `customer`, `staff`, `admin` 셋이다 | 고객센터 직원과 운영자를 나눈다 | 사람 |
| D5 | 배송은 `paid`인 주문만 시작한다 | 결제 전 출고를 막는다 | 사람 |

## 2. 주문

장바구니를 확정하면 주문(`orders`)을 만든다. 주문은 고객, 상품 줄, 합계, 상태를 가진다(D1, D3).

## 3. 결제

주문을 확정하면 결제사 API를 동기로 호출한다. 응답이 성공이면 주문을 `paid`로 바꾸고, 실패면 `pending_payment`로 둔다(D2).

## 4. 배송

`paid`인 주문만 출고한다(D5). 출고하면 `shipped`, 받으면 `delivered`다.

## 5. 정하지 않은 것

- 주문 취소와 환불 — 아직 요구가 없다
