# relay 사용법 (요약)

relay는 Claude Code CLI를 앱 안의 터미널에 띄우고, 버그 수정을 단계(task)로 나눠 진행하는 데스크톱 앱이다.

- 화면: 왼쪽은 프로젝트와 Work 목록, 가운데는 지금 단계의 터미널(에이전트 세션), 오른쪽은 승인 패널([요약], [산출물], [변경] 탭)이다. 프로젝트는 이미 등록되어 있다.
- [새 Work]에 요청(버그 설명)을 쓰고 [시작]하면 단계가 차례로 진행된다. Work마다 git worktree와 브랜치(`relay/<work-id>`)가 따로 생기고, 에이전트가 단계마다 커밋한다. 다른 설정은 기본값 그대로 두어도 된다.
- 단계: 의도 정리 → (크기에 따라) 재현과 원인 분석 → 수정 → 리뷰 → 최종 검증. 크기 S는 재현과 원인 분석을 건너뛰고, M은 한 단계로, L은 두 단계로 한다. 크기는 의도 승인 화면에서 확정한다.
- 단계마다 새 에이전트 세션이 뜬다. 에이전트가 산출물을 쓰고 "승인 대기"가 되면 오른쪽 패널에서 확인하고 [승인]한다(의도 정리는 [의도 승인]). 고칠 점이 있으면 승인하지 말고 터미널에서 에이전트에게 말한다. 에이전트가 고쳐 다시 승인 대기가 된다.
- 에이전트가 선택지로 질문하면 터미널에서 방향키와 Enter로 고르거나 글로 답한다.
- 리뷰 단계는 변경에 대한 지적 목록을 보인다. 반영할 지적을 터미널로 말하거나(예: "1번만 반영해 주세요") 그대로 승인한다.
- 최종 검증을 승인하는 화면이 Work 완료 화면이다: [완료만] / [push] / [PR 생성]. 이 평가에서는 [완료만]이면 된다.
- 되돌아가기: [단계 선택]으로 앞 단계로 되감거나(그 뒤 산출물은 폐기되고 코드도 되돌리며, 추가 지시를 줄 수 있다) 다른 단계로 갈 수 있다. 요구 자체를 바꾸려면 의도 정리로 되감는다.
- [즉시 중단]은 지금 세션을 끝내고, [재개]로 같은 세션을 다시 연다. 앱이 꺼졌다 켜지면 끊긴 task를 [재개]로 이어 간다.
- 그 밖에 [이 단계 끝나면 멈춤], [Work 설정](단계별 자동 승인 등), [Work 포기], [Work 정리](완료 뒤 worktree 제거)가 있다.
- 여러 Work를 동시에 진행할 수 있다. 각 Work는 따로 브랜치에서 진행된다.
- push와 PR은 에이전트가 아니라 앱이 한다.
