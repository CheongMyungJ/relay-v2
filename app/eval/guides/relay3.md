# relay-v3 사용법 (요약)

relay-v3는 Claude Code CLI를 앱 안의 터미널에 띄우는 데스크톱 앱이다. 일을 맡기면 세션이 먼저 계약(일이 끝났을 때 참이어야 하는 것)을 쓰고, 사람이 계약을 승인하면 세션이 알아서 구현하고, 앱이 증거(시험 결과 등)를 재서 보여 준다. 업무 유형이나 단계는 없다.

- 화면: 왼쪽 사이드바는 프로젝트와 그 아래 Work 목록([+ 새 Work], 톱니는 프로젝트 설정), 가운데는 고른 Work의 세션 터미널, 오른쪽은 패널 탭 [계약] [증거] [변경] [빚]이다. 위 머리줄에 요청의 첫 줄, Work 상태(계약 초안 / 승인 기다림 / 구현 중 / 계약 다시 / 끝남 / 버림), 세션 상태(일하는 중, 쉬는 중, 답을 기다림, 멈춤), `작업 브랜치 ← 기준 브랜치`와 [끝내기] [버리기]가 있다. 프로젝트는 이미 등록되어 있다.
- [+ 새 Work]에서 요청을 쓰고 [만들기]를 누른다. 일의 성격 제안(버그 고침 / 기능 / 리팩터링 / 문서 칩, 또는 직접 쓰기)과 기준 브랜치(기본 main)는 고르지 않아도 된다. Work마다 git worktree와 작업 브랜치(`relay/<요청에서 딴 짧은 이름>-<4자>`)가 따로 생기고 세션 하나가 뜬다. 프로젝트 설정(톱니)은 기본값 그대로 두어도 된다.
- 계약 초안: 세션이 요청과 코드를 읽고 사람만 아는 것을 터미널에서 하나씩 묻는다(결정마다 확인). 선택지로 물으면 방향키와 Enter로 고르거나 글로 답한다. 묻는 동안 [계약] 탭에는 "아직 계약이 없습니다"가 보인다.
- 계약: 세션이 계약을 내면 상태가 '승인 기다림'이 되고 [계약] 탭에 목표, 줄(줄마다 종류: 바뀜 / 새로 / 지킴 / 없앰 / 관찰 / 사람, 글, 근거와 확인됨·추정 표시, 예시 입력 → 출력이나 오류, 확인 방법: 시험 / 관찰 / 사람), 비목표, 사람만 아는 규칙이 보인다. 위의 상자에서 [승인]하거나, 고칠 점이 있으면 상자의 '고칠 점' 칸(늘 보인다)에 쓰고 [보내기]한다. 세션이 고쳐 다시 낸다. 세션은 계약 도구로 사람의 답을 기다리는 중이라, 그동안 터미널에 친 말은 패널로 답한 뒤에야 세션에 닿는다.
- 구현: 승인하면 상태가 '구현 중'이 되고 세션이 알아서 구현하고 커밋한다(방식은 세션이 정한다). 세션은 계약의 예시를 `.relay/examples/<계약 id>.json`에 커밋하고, 시험 이름에 계약 줄의 태그(예: `[<계약 id>:C1.1]`)를 붙인다. 지켜보다가 방향이 틀렸거나 고칠 것이 있으면 터미널에 말한다. 세션이 계약을 바꿔야 하면 상태가 '계약 다시'가 되고 [계약] 탭에 세션의 까닭과 새 계약이 뜬다. [받아들이기]나 [거절하기]로 답한다(세션에게 줄 말은 선택).
- 증거: 세션이 커밋하고 쉬면 20초쯤 뒤 앱이 레포의 품질 기준(`.relay/quality.json`)에 적힌 명령을 기준 커밋과 지금 커밋에서 돌리고, 계약 줄마다 태그 붙은 시험으로 판정한다. 커밋하지 않은 변경은 재지 않는다. [증거] 탭 맨 위에 결론(사람 머지 / 자동 머지 후보 / 계약 다시)과 결론을 정한 사실 한 줄, 다음 할 일이 보인다. 펼치면 사람에게 보낸 까닭, 명령(통과 / 실패 / 원래 실패), 줄 판정(충족 / 못 미침 / 증거 없음 / 사람 확인 / 관찰 확인), 래칫, 신호, 리뷰 지적, 없는 증거가 있다. 레포에 품질 기준이 없으면 명령을 돌리지 않는다. [증거 다시 재기]로 지금 커밋을 다시 잰다. 결론의 '그림자: 자동이었으면 머지했을 것'은 기록일 뿐 머지하지 않는다.
- [변경] 탭은 기준 대비 바뀐 파일과 파일마다의 diff(눌러 펼침)이고, [빚] 탭은 이 Work가 건드린 경로의 빚 항목이다.
- 독립 리뷰: 새 맥락의 읽기 전용 claude가 변경을 리뷰한다. 증거가 통과하고 세션이 쉬면 미리 돌고, PR을 열거나 갱신할 때와 [끝내기] 때도 돈다(같은 커밋을 이미 리뷰했으면 다시 돌리지 않는다). 지적은 [증거]의 리뷰 지적에 '올림'(관문이 사람에게 보냄)과 '메모'로 나뉘어 보인다. 리뷰가 꺼진 앱에서는 리뷰 자리에 '리뷰가 꺼져 있음'이 보이고 지적은 없다.
- 세션에 넘기기: 앱은 세션 몫의 사실(못 미친 줄, 실패한 명령 같은 증거의 실패와, 코드 안에서 고칠 리뷰 올림)을 쉬는 세션에 저절로 보낸다(Work마다 세 번까지). 터미널에 들어가는 'relay feedback …' 한 줄이 그것이고, [증거]의 결론 아래 한 줄이 보낸 것이나 보내지 않은 까닭을 알린다. 네가 1분 안에 터미널에 입력했거나 입력 칸에 쓰다 둔 글이 있으면 미룬다. 계약 밖 변경, 요청과 어긋남 같은 사람 몫의 지적과 저절로 가지 않은 지적은 세션에 가지 않는다. 세션이 그것을 보게 하려면 그 지적 옆의 [세션에 넘기기]를 누르거나 터미널에서 말한다.
- 끝: 보통은 세션이 작업 브랜치를 push하고 PR을 열면 [증거]의 [머지]로 끝낸다. 이 평가에서는 PR을 만들 수 없다(gh가 로그인되어 있지 않다). 세션이 끝났다고 하면 터미널과 [변경]으로 확인하고, 고칠 것은 터미널에 말한다. 커밋하지 않은 변경은 증거에도 끝에도 들지 않는다. 끝의 기준을 채웠다고 보면 머리줄의 [끝내기]를 누른다. 앱이 [증거] 탭으로 옮겨 지금 커밋의 내보내기 증거(리뷰 포함)를 본다.
  1. 열린 것(사람이 보고 정할 사실)이 없으면 Work가 바로 '끝남'이 된다.
  2. 리뷰나 증거 재기가 아직 돌고 있으면 머리줄 단추가 '리뷰 끝나면 끝냄'(누를 수 없음)으로 바뀌고 [증거]에 '끝내기가 걸려 있습니다' 상자와 [취소]가 보인다. 기다리면 다 끝난 뒤 열린 것이 없으면 Work가 끝나고, 있으면 3의 상자가 뜬다. [취소]는 걸린 끝을 푼다. 리뷰가 꺼진 앱에서는 단추가 '재면 끝냄'이다.
  3. 열린 것이 있으면 [증거]에 '열린 것이 있습니다' 상자가 열린 것만 보인다. 단추는 [그래도 끝내기](이 커밋 그대로 끝냄), [더 고치기](상자를 닫는다. 고칠 것은 터미널에서 세션에게 말한다), 그리고 열린 것에 리뷰 올림이 있으면 [세션에 넘기기](그 올림을 세션에 보내고 상자를 닫는다)다. 리뷰가 실패했으면 열린 것에 그렇게 보이고, [끝내기]를 다시 누르면 리뷰를 다시 돌린다.
  4. 세션이 새로 커밋하면 걸린 끝이나 상자가 사라지고 '[끝내기] 뒤 세션이 새로 커밋했습니다'가 보인다. 다 고친 뒤 [끝내기]를 다시 눌러 새 커밋을 본다.
  5. Work가 '끝남'이 되면 세션이 닫힌다(다시 열 수 없다). 상태가 '끝남'이 되면 평가를 끝낸다.
- 세션이 멈추면(머리줄에 '세션 멈춤') [다시 열기]로 같은 대화를 이어 연다. [버리기]는 Work를 버린다(브랜치와 worktree는 남는다).
- relay가 막는 것은 기준 브랜치(main)로의 push, 강제 push, 원격 브랜치 삭제, PR 머지 같은 되돌리기 어려운 git·gh 동작이다. 작업 브랜치 push와 PR 열기는 세션이 한다.
- 여러 Work를 동시에 진행할 수 있다. 각 Work는 따로 브랜치에서 진행된다.
