# relay 사용법 (요약)

relay는 Claude Code CLI를 앱 안의 터미널에 띄우고, 버그 수정, 기능 추가, 리팩터링을 단계(task)로 나눠 진행하는 데스크톱 앱이다.

- 화면: 왼쪽은 프로젝트와 Work 목록, 가운데 위는 단계 탭, 그 아래는 고른 단계의 터미널(에이전트 세션), 오른쪽은 고른 단계의 패널(진행 상황, 승인할 때는 [요약], [산출물], [변경] 탭)이다. 프로젝트는 이미 등록되어 있다.
- [새 Work]에서 유형(버그 수정 / 기능 추가 / 리팩터링)을 고르고 요청(버그 설명, 만들 기능, 바꿀 구조)을 쓴 뒤 [시작]하면 단계가 차례로 진행된다. 유형은 기본 선택이 없어 고르기 전에는 [시작]이 꺼져 있다. 잘못 골랐으면 의도 정리에 말한다. 의도 정리가 맞는 유형으로 Work 초안을 쓰면 오른쪽 패널의 초안 카드에서 [새 Work로 만들기]로 다시 만든다. Work마다 git worktree와 브랜치(`relay/<work-id>`)가 따로 생기고, 에이전트가 단계마다 커밋한다. 다른 설정은 기본값 그대로 두어도 된다.
- 단계: 버그 수정은 의도 정리 → 원인 분석과 수정 → 리뷰와 검증. 기능 추가는 의도 정리 → 설계와 계획 → 구현 → 리뷰와 검증이다. 설계와 계획은 유저 시나리오, 요구사항, 구현 계획을 쓰고 코드는 바꾸지 않는다. 구현은 테스트를 먼저 쓰고 구현한다. 원인 분석과 수정, 구현, 계획과 리팩터링은 기본으로 자동 승인된다(15초 카운트다운 중 [취소]로 멈출 수 있다). 리팩터링은 의도 정리 → 계획과 리팩터링 → 리뷰와 검증이다. 계획과 리팩터링은 지금 동작을 잡는 안전망 테스트를 먼저 커밋한 뒤 구조를 단계마다 바꿔 커밋하고, 동작은 바꾸지 않는다(찾은 버그는 고치지 않고 적는다). 설계와 계획은 사람이 승인한다. 자동 승인되면 화면은 다음 단계로 넘어간다.
- 지난 단계 다시 보기: 가운데 위의 단계 탭(예: `02 원인 분석과 수정`, `03 구현`)을 누르면 오른쪽 패널에 그 단계의 [요약](원인이나 설계, 결정, 위험), [산출물], [변경](그 단계의 diff)이 읽기 전용으로 뜬다. 자동 승인으로 지나간 단계도 여기서 본다. 지금 단계 탭을 누르면 다시 지금 단계를 따라간다.
- 단계마다 새 에이전트 세션이 뜬다. 에이전트가 산출물을 쓰고 "승인 대기"가 되면 오른쪽 패널에서 확인하고 [승인]한다(의도 정리는 [의도 승인]). 고칠 점이 있으면 승인하지 말고 터미널에서 에이전트에게 말한다. 에이전트가 고쳐 다시 승인 대기가 된다.
- 에이전트가 선택지로 질문하면 터미널에서 방향키와 Enter로 고르거나 글로 답한다.
- 리뷰와 검증 단계는 변경을 리뷰하고, 지적이 있으면 어느 지적을 반영할지 선택지로 묻는다. 고른 지적을 고친 뒤 완료조건을 판정한다.
- 리뷰와 검증을 승인하는 화면이 Work 완료 화면이다: [완료만] / [push] / [PR 생성]. 이 평가에서는 [완료만]이면 된다.
- 고치기와 다시 하기: 앞 단계로 돌아가는 버튼은 없다. 고칠 것은 지금 단계의 터미널에 말하면 그 단계가 고친다(리뷰와 검증도 찾은 문제나 실패한 완료조건을 그 자리에서 고친다). 요구 자체를 바꾸거나 근본부터 다시 하려면 지금 단계나 [곁 세션 열기]로 연 곁 세션에 그렇게 말한다. 에이전트가 새 Work의 초안을 쓰면 오른쪽 패널의 초안 카드에서 [새 Work로 만들기]를 누르고, 대화상자의 "원래 Work 포기"로 이 Work를 끝낸다.
- [즉시 중단]은 지금 세션을 끝내고, [재개]로 같은 세션을 다시 연다. 앱이 꺼졌다 켜지면 끊긴 task를 [재개]로 이어 간다.
- 그 밖에 [이 단계 끝나면 멈춤], [Work 설정](단계별 자동 승인 등), [Work 포기], [Work 정리](완료 뒤 worktree 제거)가 있다.
- 여러 Work를 동시에 진행할 수 있다. 각 Work는 따로 브랜치에서 진행된다.
- push와 PR은 에이전트가 아니라 앱이 한다.
